## 一、总体目标与阶段划分

### 用户的长远目标

构建一个**统一的因子评价与组合系统**，让库中所有因子都能被计算、预处理、评价、组合，并支持自定义因子构建。

### 四个阶段

```
阶段一: 基础引擎完善 (近期目标)
  → 所有因子都能被计算、预处理、评价性能
  ↓
阶段二: 因子组合分析 (下一步目标)
  → 选出一组因子, 做相关性/主成分/加权分析
  ↓
阶段三: 自定义因子构建 (再下一步目标)
  → 基于基础因子构建复合因子, 全流程评价
  ↓
阶段四: 引擎扩展 (最后阶段)
  → 支持结构/打分/回归/微观结构等更多因子类型
```

### 引擎优先级 (用户确认)

## 二、关键问题分析

### 2.1 标的/时间段/评价场景

#### 三个维度

**1. 标的维度 (自选)**:
- 因子的有效性依赖于股票池, 不同标的适用的因子可能不同
- 评价接口应支持自选标的: 全市场 / 指数成分 / 自选股池 / 单只股票
- 当前evaluate_expression接受panel参数, 调用时传入股票池, 引擎本身不限定
- **需要新增**: 股票池选择功能(前端下拉/多选)

**2. 时间段维度 (评价区间)**:
- 因子不是全时间段都有效, 需要按时间段评价
- 用户指的"周期"是评价的时间区间, 如"2026年1月到5月"
- 不是日K/周K的数据频率, 而是回测的时间窗口
- **需要支持**: start_date / end_date 参数, 评价结果按时间段给出

**3. 评价场景 (选股截面 vs 择时时序)**:

用户澄清: 因子库页面默认是**评价性能**, 不绑定未来是选股还是择时。但评价性能时可以同时考虑两种场景:

| 评价场景 | 数据使用 | 评价逻辑 | 参考 |
|---------|---------|---------|------|
| **选股(截面)** | 多只股票的收盘价截面 | 打分高买入/打分低卖出, 看多空收益 | 清华PerformanceWithCost, IC |
| **择时(时序)** | 单只股票的时间序列 | 得分高买入/得分低卖出, 看时序收益 | 信号评价 |

- **选股评价**: 在同一时间截面, 跨股票比较因子值, 高分买入低分卖出
- **择时评价**: 针对单只股票, 时间序列上因子值高时买入、低时卖出
- **框架应同时支持两种评价**, 让用户看到因子在选股和择时两个场景下的表现

#### 参考已有实践

- **清华day1_A**: SDate/EDate选择评价区间, PerformanceWithCost做截面选股评价
- **清华day2_M**: GetPortRet做固定持仓数量组合(选股), IdioRet做时序评价
- **CASE-C**: prices_panel传入股票池, IC做截面评价, min_warmup控制预热

#### 设计方向

```python
def evaluate_factor(factor_id,
                    stock_pool="all",      # 全市场/指数/自选股/单股票
                    start_date=None,       # 评价开始日期
                    end_date=None,         # 评价结束日期
                    eval_scenes=None):     # ["cross_section", "time_series"] 默认两者都做
    """
    统一因子评价入口
    - stock_pool: 自选标的
    - start_date/end_date: 评价时间段
    - eval_scenes: 评价场景(选股截面/择时时序)
    """

    results = {}
    if "cross_section" in eval_scenes:

    if "time_series" in eval_scenes:
```

| 行业中性化 | 低(已有, 保留) | CASE-C | 不作为重点 |

```python
def sector_neutralize(factor_series, sector_map, method="zscore"):
    """板块中性化
    sector_map: {stock_code: sector_name}
    method: "zscore" / "rank"
    """
    if method == "zscore":
        # 板块内Z-score: (x - 板块均值) / 板块标准差
        for sector, group in df.groupby("sector"):
            result[group.index] = zscore(group["factor"])

def concept_neutralize(factor_series, concept_map, method="zscore"):
    """概念中性化

    """

def neutralize(factor_series,
               sector_map=None,     # 板块中性化(优先)
               concept_map=None,    # 概念中性化(优先)
               industry_map=None,   # 行业中性化(可选, 保留)
               method="zscore"):    # zscore/rank
    """统一中性化入口
    可选组合: 板块+概念, 板块, 概念, 行业
    """
```

#### 问题提出

用户指出: "财务因子我现在是能获得到的，为什么说让财务因子可计算是一个价值？"

#### 澄清

**数据获取 vs 引擎计算**:

| 层面 | 现状 | 问题 |
|------|------|------|
| 数据获取 | 财务数据已在数据库中 | 无问题 |
| 表达式引擎 | 白名单有PE/PB/ROE字段 | **但panel中没有这些列** |

### 2.4 因子类型与评价场景

#### 问题提出

用户澄清: "选股和择时是下一个阶段的事情，但是评价性能可以去同时去考虑"。
- **选股**: 用不同股票的收盘价截面, 打分高买入/低卖出 (清华PerformanceWithCost的做法)
- **择时**: 针对单只股票的时间序列, 得分高买入/低卖出

#### 评价场景设计

因子库页面评价性能时, **同时输出选股和择时两种评价结果**:

| 评价场景 | 输入 | 评价方法 | 输出指标 |
|---------|------|---------|---------|
| **选股(截面)** | 多股票某时点因子值 | IC + 分层回测 + 多空收益 | IC/IR/分层收益/夏普 |
| **择时(时序)** | 单股票时序因子值 | 信号胜率 + 因子值分组收益 | 胜率/盈亏比/时序收益 |

#### 不同因子类型的默认评价

| 因子类型 | 选股评价 | 择时评价 | 说明 |
|---------|---------|---------|------|
| 价量/动量/波动/技术/均线 | 是(截面IC+分层) | 是(时序信号) | 两种场景都适合 |
| 财务因子(PE/PB/ROE) | 是(截面IC+分层) | 弱(更新慢) | 主要用于选股 |
| WQ复合因子 | 是(截面IC+分层) | 是(时序信号) | 两种场景都适合 |
| 交互因子 | 是(截面IC+分层) | 是(时序信号) | 两种场景都适合 |
| K线形态(离散) | 弱(离散值IC意义小) | 是(信号胜率) | 主要用于择时 |

#### 设计方向

```python
def evaluate_factor(factor_id, stock_pool, start_date, end_date):
    # 同时做选股和择时评价
    factor_values = calc_factor(factor_id, panel)
    
    # 1. 选股评价(截面)
    cross_section_result = {
        "ic": calc_ic(factor_values, future_returns),  # 截面IC
        "layered": run_layered_backtest(...),           # 分层回测
        "long_short": calc_long_short_return(...),      # 多空收益
    }
    
    # 2. 择时评价(时序)
    time_series_result = {
        "win_rate": calc_signal_win_rate(factor_values, returns),  # 信号胜率
        "group_return": calc_group_return_by_factor_level(...),     # 按因子值分组的时序收益
    }
    
    return {
        "cross_section": cross_section_result,  # 选股评价
        "time_series": time_series_result,      # 择时评价
    }
```

### 与任务一的结合: formula构建与因子来源包装

用户指出: "阶段一也是需要和任务一结合, 就是我的因子表里的formula该如何构建？不同来源的因子有的通过本地函数调取本地数据直接计算, 有的需要借用第三方函数计算, 怎么合理包装起来"。

#### 因子来源分类与包装策略

| 因子来源 | 计算方式 | formula形式 | 包装策略 |
|---------|---------|------------|---------|
| **本地数据+表达式** | ts_*/cs_*算子 + OHLCV | `ts_RSI(Close, 14)` | 表达式引擎直接执行 |
| **本地数据+Talib** | talib函数 | `ts_MACD_HIST(Close, 12, 26, 9)` | 封装为ts_*函数 |
| **本地财务数据** | FN(field)函数 | `Close / FN(eps)` | FN函数接入财务数据库 |
| **本地数据+自定义函数** | 本地Python函数 | `chan_divergence()` | 注册到引擎命名空间 |
| **第三方函数** | 外部库调用 | `ta_CDLHAMMER(O,H,L,C)` | 封装为ta_*函数 |

#### formula设计原则

1. **自包含**: formula直接存储计算方式, 无需通过基类组装还原
2. **分层引用**: 交互因子可引用其他因子的值(dependencies)
3. **来源无关**: 无论数据来自本地还是第三方, formula统一用函数调用表达
4. **可执行**: formula是可被eval()执行的真实代码, 不是文字描述


#### 引擎统一入口设计

```python
def calc_factor(factor_id, panel, **kwargs):
    """统一因子计算入口 - 合理包装不同来源"""
    factor = get_factor(factor_id)
    formula = factor["formula"]
    dependencies = factor.get("dependencies", [])
    calc_engine = factor.get("calc_engine", "expression")  # expression/talib/financial/chan/dragon
    
    # 根据计算引擎选择执行方式
    if calc_engine == "expression":
        if dependencies:
            return evaluate_expression_with_deps(formula, panel, dependencies)
        else:
            return evaluate_expression(formula, panel)
    elif calc_engine == "chan":
        return chan_engine.calc(panel)
    elif calc_engine == "dragon":
        return dragon_engine.calc(panel, kwargs.get("market_data"))
    else:
        return evaluate_expression(formula, panel)  # 默认表达式引擎
```

#### 1.3 因子间引用 (交互因子支持)

**目标**: 让交互因子(如adx_rsi_cross)能引用其他因子的值

**实现方案**:

```python
def evaluate_expression_with_deps(expr, panel, dependencies):
    """支持依赖因子的表达式计算
    1. 先计算每个依赖因子的值
    2. 将依赖因子值注入命名空间
    3. 执行表达式
    """
    namespace = build_namespace(panel)
    
    for dep_factor_id in dependencies:
        dep_factor = get_factor(dep_factor_id)
        dep_value = evaluate_expression(dep_factor["formula"], panel)
        namespace[dep_factor_id] = dep_value  # 注入依赖因子值
    
    result = eval(expr, {"__builtins__": {}}, namespace)
    return result
```

**交互因子表达式示例**:
```
# adx_rsi_cross
```

```python
def evaluate_factor(factor_id, 
                    stock_pool="all",         # 自选标的: 全市场/指数/自选股/单股票
                    start_date=None,          # 评价时间段-开始
                    end_date=None,            # 评价时间段-结束
                    rebal_period=None,        # 调仓周期(None=自动)
                    neutralize_method="sector",  # sector/concept/industry/none
                    eval_scenes=None):        # ["cross_section","time_series"] None=都做
    """统一因子评价入口
    - stock_pool: 自选标的(全市场/指数成分/自选股池/单股票)
    - start_date/end_date: 评价时间段(因子不是全时段有效, 按区间评价)
    - eval_scenes: 评价场景(选股截面 + 择时时序)
    """
    
    # 1. 读取因子信息
    factor = get_factor(factor_id)
    formula = factor["formula"]
    dependencies = factor.get("dependencies", [])
    
    # 2. 加载数据(按标的和时间段)
    panel = load_price_data(stock_pool, start_date, end_date)
    sector_map = load_sector_map(stock_pool)    # 板块数据(优先)
    concept_map = load_concept_map(stock_pool)  # 概念数据(优先)
    
    # 3. 自动选择参数
    if rebal_period is None:
        rebal_period = 63 if factor.category == "基本面" else 21
    if eval_scenes is None:
        eval_scenes = ["cross_section", "time_series"]  # 默认两种都做
    
    # 4. 计算因子值
    factor_values = calc_factor(factor_id, panel)  # 统一入口(阶段一与任务一结合)
    
    # 5. 预处理(板块/概念中性化优先)
    factor_processed = preprocess_factors(factor_values, 
                                          sector_map, concept_map,
                                          method=neutralize_method)
    
    # 6. 双场景评价
    result = {}
    if "cross_section" in eval_scenes:
        # 选股评价: 截面IC + 分层 + 多空收益
        result["cross_section"] = run_cross_section_eval(
            factor_processed, panel, rebal_period)
    if "time_series" in eval_scenes:
        # 择时评价: 单股票时序信号胜率 + 因子值分组收益
        result["time_series"] = run_time_series_eval(
            factor_processed, panel)
    
    return result
```

```python
                     method="optuna",        # optuna/scipy/grid
                     objective="sharpe",      # sharpe/ic_ir/long_short
                     n_trials=100):
    """自动优化因子权重
    - method="optuna": 用Optuna贝叶斯优化搜索最优权重
    - method="scipy": 用scipy.optimize.minimize
    - method="grid": 网格搜索(因子少时)
    - objective: 优化目标(夏普/IC_IR/多空收益)
    """

        def objective_fn(trial):
            weights = [trial.suggest_float(f"w_{i}", 0, 1) for i in range(n_factors)]
            weights = np.array(weights) / sum(weights)  # 归一化

            if objective == "sharpe":
                return calc_sharpe(composite, future_returns)
            elif objective == "ic_ir":

        study = optuna.create_study(direction="maximize")
```

## 八、风险与注意事项

### 8.1 数据对齐问题

- 财务数据是季度更新, 日K是每日更新, 需要ffill对齐
- 使用fin_Delay避免未来函数(只能用已公布的财报)
- 不同股票的上市时间不同, 需要处理新股数据不足

### 8.2 性能问题

- 235个因子 × 全市场股票 × 多年日K = 计算量大
- Talib函数需逐股票遍历, 可能较慢
- 建议支持增量计算和结果缓存

### 8.3 评价一致性

- 不同因子类型的评价方式不同(连续值用IC, 离散值用信号评价)
- 需要确保评价结果可比(IC/IR的口径一致)
- 调仓周期应根据因子类型自动调整

### 8.4 向后兼容

- 现有的calc_basic_factors()保留, 不破坏已有功能
- evaluate_expression()保持向后兼容, 新增函数加入白名单
- 评价接口新增evaluate_factor(), 原有接口不变
