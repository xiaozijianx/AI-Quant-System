## 〇、结论速览

1. **三类处理方式内部的"正统成员"路由基本正确**(CDL→pattern、FN财务→financial、连续技术因子→technical), 但 technical 是无差别兜底, 混入了 71 个应走事件评价的离散因子和 19 个量纲不可比因子
2. **需要新增第四种评价方式 `technical_ts`**(时序标准化截面评价): 价格水平/累积量纲/绝对波动类因子先对自身历史做滚动分位, 再走截面管线; 不改因子公式, 只改评价预处理
3. **pattern 需正名为 `signal`**(事件信号型)并增加方向感知: K线形态只是事件信号的子类, 二值因子(新高/新低/HT_TRENDMODE)可复用同一评价框架
4. **入口逻辑从"公式嗅探"改为"显式标签"**: factor_library 新增 evaluation_type 列, 路由优先读标签, 公式规则只作落库时的默认值推断(兜底)
5. **WQ系列考证**(对照清华 day1_A/day2_M 原版): IdioRet 移植正确; **TotalRet 语义错位(真实bug, 影响 WQ_TOTALRET_DECAY)**; cs_Mean 名不副实(实际为去均值)曾导致误判; WQ_IDIO_RET 为冗余因子(清华原版中 IdioRet 只是中间变量)
6. **D组34个不可计算因子**(dragon/微观结构/缠论/Barra/ML)按用户指示本期不处理, 仅在文档中登记

## 一、三类处理方式的隐含假设 (审计基准)

| 处理方式 | 数学假设 | 隐含前提 |
|---|---|---|
| technical (IC时序+分层+PWC) | 截面排序与未来收益单调相关 | ① 因子值连续分布 ② **跨股票量纲可比**(不能是绝对价格/累积量) ③ 排序有意义 |
| pattern (信号评价) | 离散三态: 0=无信号, 正=看涨, 负=看跌 (talib CDL约定) | ① 值域离散 ② 信号稀疏 ③ 符号有方向语义 |
| financial (财报期对齐IC) | 值随财报期阶梯跳变 | ① 数据源为季度财报 ② 日内值不变 |

现行入口 (`factor_engine.classify_factor_type`, 3条规则):
```
fid 以 CDL_ 开头 或 formula 含 ta_cdl  → pattern
formula 含 FN( 或 category == fundamental → financial
其余 → technical (无差别兜底)
```

入口逻辑的三个结构性问题:
1. **technical 兜底是"垃圾桶"**: 二值因子和量纲不可比因子被塞进 IC/分层流程, 产出失真结果而非报错
2. **不可计算因子没有第四态**: 34个文字formula因子在 Tab4 点击报错、在批量评估中被 `_is_evaluable_factor` 静默跳过, 用户无法区分"评了没结果"和"根本评不了"
3. **pattern 规则过窄**: 只认 talib CDL, 其他离散事件因子(20日新高/新低、HT_TRENDMODE)漏网进 technical

### B组: 二值离散, 现路由 technical 失真 (3个 → signal)

| 因子 | formula | 问题 | 新路由 |
|---|---|---|---|
| new_high_20d | (High >= ts_Max(High, 20)) * 1.0 | 0/1二值: qcut因duplicates=drop退化成2层, 分层单调性失真; 去极值/中性化对二值变量无益 | signal(看涨事件, direction=positive) |
| new_low_20d | (Low <= ts_Min(Low, 20)) * 1.0 | 同上; 且现pattern评价约定"正值=看涨", 直接归入会被误判为看涨信号 | signal(看跌事件, direction=negative, 需方向感知) |

说明: 二值因子的截面IC在统计上并非无效(等价两组收益差检验), 丢失的是分层单调性展示; 事件语义评价(信号频率/命中率/条件超额)信息量更大且与因子含义一致, 故以signal为主。不改公式(不在公式里乘-1对齐talib符号), 由评价函数按direction解释极性。

### C组: 量纲不可比, 现路由 technical 结果无意义 (19个 → technical_ts)

| 子组 | 因子 | 为什么截面IC无意义 |
|---|---|---|
| 均线绝对值(9) | TALIB_SMA/EMA/WMA/DEMA/TEMA/KAMA/TRIMA/MAMA/SAR | 值=价格水平, 截面排序实为"高价股vs低价股"(混杂规模效应), 与均线语义无关 |
| 价格变换(4) | TALIB_AVGPRICE/MEDPRICE/TYPPRICE/WCLPRICE | 同上 |
| 回归类价格量纲(2) | TALIB_LINREG、TALIB_LINREG_INTERCEPT | 回归投影值/截距为价格量纲 |
| 累积量纲(2) | TALIB_OBV、TALIB_AD | 随时间单调累积, 截面比较=规模/上市时长代理 (ADOSC已比率化无此问题; obv_slope_10d是正确范例) |
| 绝对波动(2) | TALIB_STDDEV、TALIB_VAR | 价格量纲的绝对波动, 高价股天然大 (NATR才是归一化版本) |

这些因子不会报错, 会给出"看起来正常但语义错误"的IC——比报错更危险。

**为何现有三类都不合适**: technical直接截面=测规模效应; pattern=事件语义不符(这些是连续水平量); financial=无财报结构。**新增第四种评价方式 technical_ts(时序标准化截面评价)**:
- 预处理管线: 每只股票的因子值先对自身历史做滚动分位排名(默认250交易日, 参数可调) → 转成"处于自身历史的分位"[0,1], 跨股票可比 → 再走现有截面管线(去极值→中性化→zscore→IC/分层/PWC)
- 语义效果: 20日均线→"均线处于自身一年分位"(趋势位置); OBV/量→"量能处于自身历史分位"(≈量比语义); STDDEV→"波动状态分位"
- 不改因子公式, 只改评价侧预处理, 符合"因子匹配到正确的处理类路由"的原则
- 备选方案(不采用): 改公式归一化(SMA→bias、STDDEV→NATR)违背用户"不改计算方式"偏好; 且会引入新因子而非复用原因子

原始字段字段因子(10个 → none, 不参与独立评价): open/high/low/close/volume/amount/vwap/value/idioret/totalret
- 纯构造中间字段, 无独立评价意义(close的截面IC=纯规模效应; idioret与returns(1)排序完全等价; totalret见WQ考证)
- turnover_rate 例外: 真换手率截面可比, 保持 technical

## 三、WQ系列与清华原版考证 (2026-08-15)

> 对照对象: qinghua/day1_A.ipynb(cell 6/8/27)、day2_M.ipynb(cell 9/16/39)。
> 起因: 上轮审计标记 WQ_IDIO_RET(formula=cs_Mean(returns(1)))疑似"全市场同值→IC恒NaN", 用户要求对照清华原版核实是否移植出错。

### 3.1 纠错: WQ_IDIO_RET 本身没有算错

我们的 `cs_Mean` 名不副实(factor_engine.py:105-107):
```python
def cs_Mean(df):
    """截面均值 (每行求均值, 广播回同形状, 用于IdioRet等计算)"""
    return df.sub(df.mean(axis=1), axis=0)   # 实际返回 df - 行均值 = 去均值!
```
因此 `cs_Mean(returns(1))` = 个股收益 - 市场均值收益 = 特异质收益, **与清华 IdioRet 逐值等价**, 截面有差异、IC可正常计算。上轮"IC恒NaN"为误判(文档问题清单第29条"cs_Mean名不副实"的陷阱自己也踩了)。

### 3.2 真实bug: TotalRet 语义错位 (影响 WQ_TOTALRET_DECAY)

清华原版(day1_A cell 6+8, day2_M cell 9, 两本一致):
```python
TotalRet = getTradingDayDataFromMat(data1,'TotalRet',...)  # 注释: 日收益率面板
IndexRet = TotalRet.mean(1)
IdioRet  = TotalRet - IndexRets
```

我们的实现(factor_engine._build_field_dfs):
```python
ret = close_df.pct_change()
field_dfs["IdioRet"]  = ret.sub(ret.mean(axis=1), axis=0)   # 正确(独立计算, 与清华一致)
field_dfs["TotalRet"] = (1 + ret).cumprod()                  # 错误: 累计收益指数(价格量纲)
```

| 字段 | 清华原版 | 我们的实现 | 判定 |
|---|---|---|---|
| IdioRet | 日收益-截面均值 | pct_change()-行均值 | 正确 |
| TotalRet | 日收益率面板 | (1+ret).cumprod()累计指数 | **语义错位** |
| Value | 成交额 | amount代理 | 一致 |

受影响因子 **WQ_TOTALRET_DECAY** (清华公式: `-1*ts_Decay((ts_Decay(TotalRet,10)-ts_Decay(VWAP,10))/VWAP*(High-Low),40)`):
- 清华语义: 平滑收益率 vs VWAP 的动量偏离因子
- 我们的语义: 平滑累计指数(≈价格均线) vs VWAP, **退化为价格位置类, 与 WQ_PRICE_VOLUME 近重复**; 多因子去冗余时两者会互相误剔
- 不受影响: WQ_IDIO_VOL/WQ_IDIO_AMPLITUDE_VOL 走 idioret() 基类→IdioRet面板, 正确; 其余WQ因子输入无此问题

### 3.3 WQ_IDIO_RET 的定位

它不是清华的独立因子——原版 cell 27 公式列表里 IdioRet 只作为**中间变量**出现在两条公式中。导入时被单独存成因子, 且与库中 `idioret` 字段因子(formula=idioret())完全等值, 属冗余。

## 四、入口逻辑改造: 显式标签 evaluation_type

### 4.1 设计原则 (用户确认)

公式规则只在**落库时给默认值**, 之后路由只读显式维护的字段; 不能依赖"恰好都用 ta_CDL 实现"这类巧合——未来新抓的离散信号因子可能不含 ta_CDL, 但依然适合 signal 评价。

### 4.2 字段设计

factor_library 新增列:
```
evaluation_type VARCHAR(20) NULL
  -- technical     截面连续型 (现有IC/分层/PWC管线)
  -- technical_ts  时序标准化截面型 (新增: 先对自身历史滚动分位, 再走截面管线)
  -- signal        事件信号型 (原pattern正名; 含CDL/新高新低/趋势模式等离散事件)
  -- financial     财报期对齐型 (现有)
  -- none          不可独立评价 (构造中间字段; D组待配引擎后另行改标)
```

### 4.3 路由解析逻辑 (重构 classify_factor_type → resolve_evaluation_type)

```
1. factor_info.evaluation_type 非空 → 直接采用 (显式标签优先)
2. 为空 → 公式规则推断默认值 (仅兜底, 主要服务历史数据与旧自定义因子):
   - CDL_/ta_cdl → signal
   - FN(/fundamental → financial
   - 其余 → technical
3. 保存因子(/save /generate)时: 前端下拉默认填自动推断值, 用户可改; 落库即固化
```

调用方兼容: routes/factor.py(7处)、lib/factor_evaluator.py、lib/factor_engine.py 的 classify_factor_type 保持函数名不变、内部改为读标签优先, 返回值 pattern 归并为 signal(过渡期兼容)。

### 4.4 前端 (templates/factor.html)

- 因子库列表: 新增"评价方式"徽章列 + 筛选; none 灰色徽章
- 详情/编辑弹窗: evaluation_type 下拉(五选 + "自动"), 展示当前生效值与来源(手工/自动推断)
- Tab4单因子评价/批量分析: none 因子评价按钮置灰 + tooltip(原因); signal/technical_ts 结果区按类型展示
- 保存自定义因子表单: 加评价方式下拉, 默认自动

## 五、两种新评价方式的实现设计

### 5.1 signal 评价 (evaluate_pattern_factor → evaluate_signal_factor 改造)

保留现有框架(信号频率/命中率/条件收益), 三处改造:
1. **方向感知**: 新增 direction 参数(1/-1/0)
   - 因子值带正负号(CDL ±100): 按值符号判多空(现逻辑)
   - 因子值单极0/1(新高/新低): 按direction判多空(+1=看涨事件, -1=看跌事件)
   - direction=neutral: 只报信号超额(signal_alpha), 不做多空拆分
2. **正名**: 函数与结果键名 pattern→signal(前端展示"事件信号评价"); 旧键保留兼容已持久化的eval_result
3. **口径说明**: 信号频率解读需区分稀疏形态(CDL几个百分点)与密集事件(新高趋势股20%+), 结果区加提示文案

### 5.2 technical_ts 评价 (新增预处理分支)

- 管线: fv_ts = 逐列 rolling(w).rank pct (默认 w=250, min_periods=w/2) → 现有截面管线(去极值/中性化/zscore → IC时序/分层/PWC)
- 参数: ts_norm_window 进评价请求(默认250); min_warmup 相应增加(130+250或降低窗口, 取舍在前端提示)
- 性能: rolling rank 为 O(N*w), 80股x500日x250窗约千万级操作, pandas可接受; 如慢可换rolling apply分块
- 实现位置: run_ic_timeseries_panel / preprocess_factors 增加 ts_normalize 参数; routes /evaluate 与批量评估在 evaluation_type=technical_ts 时传入
- 多因子 B1/B2: 阶段4接入(technical_ts因子在prep时同样先做滚动分位再参与合成); 初期可先排除并提示
