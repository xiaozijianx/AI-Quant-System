## 〇、设计原则 (用户确认)

1. **清华专业能力必须迁移**: 组合风险模型(getExposure 暴露度量 / get_port_neutral 组合中性化 / 风险分解 / 归因)、PerformanceWithCost
2. **多类型组合方式保留**: 等权/IC加权/排名/Lasso/ML回归/ML分类/Sharpe/PCA 等 10 种
3. **匹配而非杂揉**: 不同合成方法对因子类型有不同要求, 需按方法匹配可用功能, 不能所有东西无差别混在一起
4. **准确处理不同类型因子**: 考虑技术/财务/信号各自信号特点
5. **因子特例不报错**: 点击任何因子都不应在多因子分析中崩溃(预检 + 优雅降级)
6. **最终产物**: 综合因子包

### 〇·五、用户已确认的设计决策 (2026-08-15)

| 决策 | 结论 |
|---|---|
| 信号(signal)因子处理 | **转方向得分独立轨**(事件评价 + 按命中率/条件收益加权成信号方向得分, 与连续合成分开, 最后汇总) |
| 财务(financial)因子 | **进连续合成**(财报可用日 asof 对齐后, 量纲统一参与合成, 调仓对齐财报期) |
| 组合风险阶段 | **默认自动分析**(每次多因子合成后自动执行 Barra 风险分析); **组合中性化为可选开关**(默认关, 可勾选) |
| 实施顺序 | **F0 → F1 → F2 → F3 → F4** (先预检容错, 再清华风险, 再多类型, 再因子包, 再回归) |

### 〇·六、风险中性化 = 双阶段框架 (2026-08-15 讨论澄清)

**风险暴露中性化不是单纯前处理或后处理, 而是双阶段**(对应清华 case 两处介入, 用户确认):

| 阶段 | 清华对应 | 作用对象 | 目的 | 现状 |
|---|---|---|---|---|
| **阶段一: 因子层面中性化(前处理)** | `F_GetResidual`(alpha 因子对 Barra 风格回归取残差) | 因子值本身 | 剥掉因子夹带的风格暴露, 得到纯 alpha, **进合成之前** | ✅ 已有(行业/板块/概念/市值维度); **F 可扩展"Barra 风格中性化"维度** |
| **阶段二: 组合层面风险分析(后处理)** | `getExposure` + `get_port_neutral` | 组合权重 | 度量/压平组合叠加出的风格赌注 | ❌ F1 新增 |

> 结论: 阶段一是前处理(已有, 属单因子/多因子预处理), 阶段二是后处理(F1 新增)。两者共同构成完整的"风险中性化"能力, 设计上必须分开表述, 不混淆。

### 〇·七、混合因子类型选择策略 (2026-08-15 讨论澄清)

用户勾选混合类型(如 15 技术 + 3 财务 + 2 信号)时:

```
连续轨: 15技术 + 3财务 = 18 个 → 按所选方法合成
信号轨: 2 个 → 方向得分独立轨
排除清单: 仅"真不兼容"因子(不可算/none/样本不足) → 自动排除 + 醒目列原因
```

**策略**: 
1. **绝不放弃整个流程** —— 部分因子不合适就剔除并明示, 其余正常合成
2. **财务因子进连续合成、信号因子独立轨**(已确认决策)化解了大部分方法×类型冲突
3. 排除仅针对"真不兼容": 不可算/none / 样本不足
4. 排除清单在结果中醒目列出(因子ID + 原因 + 建议), 不静默
5. 兜底: 有效合成因子 <2 → 降级为单因子展示 + 明确说明; 方法需协方差但连续因子不足 → 降级等权 + 警告

### 〇·八、中性化维度关系 (2026-08-15 讨论澄清)

**扩展 Barra 风格中性化维度后, 行业/板块/概念/市值维度不删, 是不同层次而非替代:**

| 维度 | 本质 | 剥掉什么 | 风格中性化能替代吗 |
|---|---|---|---|
| 行业/板块/概念 | 分类维度(离散分组哑变量) | 行业 beta(因所在行业涨而涨) | ❌ 不能(风格=连续暴露, 行业=归属, 正交) |
| 市值 | 连续规模维度 | 大小盘暴露 | ⚠️ 与风格 SIZE 有重叠, 但可单独用 |
| Barra 风格(新增) | 10 连续风格一起回归取残差 | 规模+动量+价值+波动+流动性等综合风格 | ——(自身) |

> 结论: 行业/板块/概念保留(分类维度不可替代); 市值保留(单维度直观); 风格中性化为新增的更全面选项(等价 F_GetResidual), 按需组合选择, 非升级替代。

### 〇·九、合成方法可用性 = 连续轨有效因子数 (2026-08-15 讨论澄清)

**合成方法可用性由"实际参与连续合成的有效连续因子数"决定, 而非勾选了哪些因子:**

| 选择 | 连续轨 | 信号轨 | Sharpe/IC加权/PCA 可用? |
|---|---|---|---|
| 只选技术 | 有 | 无 | ✅ |
| 技术+信号 | 有 | 有 | ✅(连续轨合成, 信号自动进信号轨) |
| 只选财务 | 有(财报对齐) | 无 | ✅ |
| 财务+信号 | 有 | 有 | ✅ |
| **只选信号** | **无** | 有 | ❌ 无连续因子 |

**三层防护**: ① 前端实时提示(连续因子数<2 时方法标灰+提示"需≥2个连续因子"); ② 后端强制兜底(强行调用返回明确错误, 不崩); ③ 引导(提示改用信号组合轨或补充连续因子)。

**补充: 信号轨自身也需要合成方式**(信号方向得分组合): 命中率加权 / 等权 / 信号数量。只选信号因子时也有路可走。

## 一、工作流适配性总判断

**结论: 适配, 但必须分层。**

清华能力(风险模型)与 10 种合成方法**并不冲突**, 原因是它们作用于流程的**不同环节**:

| 环节 | 归属 | 是否与合成方法冲突 |
|---|---|---|
| 因子值 → 合成权重 (10种方法) | 方法层 | 方法间互斥(一次选一种), 但结果都是权重 |
| 权重 → 组合(Top-N) | 通用层 | 所有方法通用 |
| 组合 → Barra风险分析(暴露/中性化/归因) | **通用层(清华)** | **对所有方法都成立, 不冲突** |
| 组合 → PerformanceWithCost/绩效 | 通用层 | 不冲突 |
| → 因子包 | 通用层 | 不冲突 |

**唯一的真实冲突点: 合成方法 × 因子类型 的兼容性。** 这正是用户担心的"不适合的地方"——某些方法(如 PCA/Markowitz/Sharpe)要求连续、标准化、有相关结构的因子; 信号因子(稀疏二值)或未对齐的财务因子混进去会失真甚至报错。

## 二、三层架构

### 层 1: 通用层 (与合成方法无关, 全部方法共享)
```
输入: 因子组(任意类型) + 股票池 + 日期 + 调仓 + 中性化 + 时序窗口
  │
  ├─ 预检(Pre-flight): 每个因子 可计算/样本充足/类型判定 → 失败标记原因, 不阻塞
  ├─ 单因子预评价(按类型 technical/technical_ts/financial/signal)
  ├─ B1 数据准备(按类型清洗/标准化/对齐)
  ├─ B2 合成(方法层产出权重)
  ├─ 组合构建(Top-N)
  ├─ 清华风险阶段(通用): Barra暴露度量 → 风险分解 → 组合中性化 → 归因
  ├─ 绩效评价(IC/分层/Top-N/基准/超额/Calmar/月度胜率/多空/换手)
  └─ 因子包(权重+方向+模型+风险快照)
```
通用层对**所有合成方法**都生效, 不存在兼容问题。

### 层 2: 方法层 (合成方法, 一次选一种)
每种合成方法**声明**它接受哪些因子类型 + 前置要求, 由系统自动匹配:

| 方法组 | 方法 | 接受的因子类型 | 前置要求 |
|---|---|---|---|
| 连续型 | equal 等权 | 技术/技术ts/财务(对齐) | 值域统一(标准化) |
| 连续型 | ic_weighted IC加权 | 技术/技术ts/财务(对齐IC) | 连续、可算IC |
| 连续型 | rank_score 排名 | 全部(信号也OK, 取rank) | 无 |
| 连续型 | lasso Lasso | 技术/技术ts/财务(对齐) | 标准化、样本充足 |
| 风险优化 | markowitz/optuna/sharpe | 仅连续因子 | **需协方差矩阵; 信号因子自动剔除** |
| 分解 | pca | 仅连续因子 | 相关结构; 信号因子自动剔除 |
| ML | ml_reg/ml_cls | 连续为主 | 标准化、缺失填充 |

### 层 3: 因子类型层 (每类型标准处理)

| 类型 | 信号特点 | 进合成标准处理 | 进 ML | 风险/相关分析 |
|---|---|---|---|---|
| technical | 连续日频、截面可比 | 直接入截面(现状) | ✅ | ✅ |
| technical_ts | 绝对量纲 | 先时序分位标准化(现状) | ✅ | ✅ |
| financial | 季度低频、阶梯跳变 | 财报可用日 asof 对齐, 对齐调仓 | ✅(填充后) | ✅ |
| signal | 离散0/1 或 -1/0/+1、稀疏 | **转"方向得分"或保持事件轨** | ⚠️(稀疏特征) | ❌(协方差失真) |

## 三、核心: 合成方法 × 因子类型 兼容矩阵 (自动匹配逻辑)

```
                technical  technical_ts  financial   signal
equal           ✅         ✅(先分位)     ✅(对齐)     ⚠️(转方向得分)
ic_weighted     ✅         ✅            ✅(对齐IC)   ⚠️(rankIC不稳)
rank_score      ✅         ✅            ✅          ✅(rank化)
lasso           ✅         ✅            ✅          ⚠️(稀疏)
ml_reg/ml_cls   ✅         ✅            ✅          ⚠️(稀疏)
markowitz       ✅         ✅            ✅          ❌(剔除)
optuna          ✅         ✅            ✅          ❌(剔除)
sharpe          ✅         ✅            ✅          ❌(剔除)
pca             ✅         ✅            ✅          ❌(剔除)
```

**自动匹配规则**:
1. 用户选方法 → 系统读该方法"接受的因子类型"
2. 选中的因子按类型归类; 不兼容的因子 → **自动移出合成(仅保留单因子评价) + 明确提示原因**, 不报错
3. 兼容但需特殊处理的(signal 转方向得分) → 自动预处理
4. 合成前检查: 有效合成因子 ≥2 才合成; 不足则只展示单因子 + 明确提示

## 五、因子特例防护 (防报错, 用户明确要求)

### 5.1 预检(Pre-flight, 合成前一次性检查)
对每个选中因子:
1. 是否存在(factor_library 有记录)
2. 是否可计算(formula 非空、无中文、可解析)
3. evaluation_type 判定(technical/technical_ts/financial/signal/none)
4. 计算是否成功、是否有足够样本(≥最小阈值)

预检结果: 每因子 {status: ok|skip|error, reason}; 失败因子**单因子评价区标记原因**, 不进合成, 不阻塞整体。

### 5.2 优雅降级规则
- 合成因子 <2 → 只展示单因子评价 + 明确提示(现状已有, 保持)
- 某因子计算异常 → 该因子标记 error, 其余正常合成
- 财务因子无财报数据 → 该因子无样本, 标记跳过
- signal 因子被连续型方法剔除 → 提示"该方法不支持信号因子, 已自动移出合成"

### 5.3 错误分级
- 致命(无有效因子/无截面)→ 返回明确错误信息
- 可降级(部分因子失败/不兼容)→ 自动跳过 + 结果中列出原因
- 不静默吞错: 所有跳过/剔除都在结果中显式列出

## 七、风险与注意

1. 财务因子入合成: 财报对齐后值低频, 合成权重更新频率需与财报一致, 避免未来函数
2. signal 转方向得分: 需按 hit_rate/条件收益加权, 不能直接当连续值
3. 协方差矩阵: 需足够历史截面, 样本不足时风险分解降级为"仅暴露度量"
4. 中性化叠加: 组合中性化与单因子中性化是不同层面, 避免双重作用误用
5. 中文注释 UTF-8, 不引入 emoji
