## 二、CDL_HIGHWAVE 公式修复 (P0)

- 现状: `lib/factor_init.py` L724-726, `CDL_HIGHWAVE`(长腿十字-高波) formula = `ta_CDLHIKKAKE(Open, High, Low, Close)`。
- 问题: 对照 TA-Lib, `CDLHIGHWAVE`(长腿十字/高波动) 与 `CDLHIKKAKE`(Hikkake 怪力线) 是**两种不同模式**; 且基类表 `CDL_HIGHWAVE` 同样映射到 `CDLHIKKAKE`。属复制粘贴错误。
- 处置: formula 改为 `ta_CDLHIGHWAVE(Open, High, Low, Close)`; 基类表 `factor_base.CDL_HIGHWAVE` 的 formula_template 同步改为 `CDLHIGHWAVE(o,h,l,c)`; 确认 `lib/factor_engine.py` 的 TA-Lib 算子白名单已含 `CDLHIGHWAVE`(L672 已确认在列)。
- 验证: 更新后重跑 run_init, 用 `ta_CDLHIGHWAVE` 计算一根已知 K 线验证输出。

## 五、合成方法认知: 同一阶段, 互斥备选 (用户确认)

10 种方法均为**"选定因子 → 综合因子输出"这一阶段的互斥实现**, 不是分层, 下拉并列合理。按机制族归类(仅用于展示理解, 不改变功能):

| 机制族 | 方法 | 综合因子 = |
|---|---|---|
| 线性加权 | `equal` / `ic_weighted` / `sharpe` / `markowitz` / `optuna` / `lasso` | Σ w_i·z_i (权重来源: 1/N / 历史IC / IC夏普 / 优化解 / 寻优 / 回归系数) |
| 排名打分 | `rank_score` | 每因子转截面排名后等权平均 |
| 模型映射 | `ml_reg` / `ml_cls` | 模型 predict(回归值) / predict_proba(买入概率), 非线性 |
| 降维投影 | `pca` | 主成分投影(多一个"先定主成分"子步骤, 仍产出一个综合因子) |

> ✅ 已实施(2026-08-15): 多因子分析页合成方式下拉按机制族 `<optgroup>` 分组(线性加权/排名打分/模型映射/降维投影); 不改后端逻辑、不改 option value, 纯 UI 归类, 非分层。

## 六、因子包跨页使用: 现状与真实缺口 (P1)

### 6.1 现状(已闭环, 非等权硬编码)

- **保存**: `POST /api/factor/package` 调用 `build_final_use_from_prep`(全历史)确定最终 `factor_ids / weights / direction / ml_model_path / pca_model_path`, 存入 factor_package; ML/PCA 模型经 `_dump_ml_model` / `_dump_pca_model` joblib 落盘到 `data/factor_packages/models/`。
- **消费**: 晨报 `morning_brief/graph.py _pick_by_package` → `score_stocks_by_package(pkg, panel)`:
  - 加权方法: 用保存的 `weights` 线性组合(方向已含在权重符号, 不二次翻号)
  - `ml_reg`/`ml_cls`: 加载模型 `predict` / `predict_proba[:,1]` 出综合得分
  - `pca`: 加载对象投影, 按解释方差加权
  - `rank_score`: 按 direction 排名打分
  - 仅无 weights 时(纯等权)按 direction 翻转后等权
- **ml_reg vs ml_cls 差异**(对因子包/晨报无影响): 两者输出都是"每股综合得分 alpha"(非权重); ml_cls=买入概率(0~1), ml_reg=回归预测值(连续); 晨报均按 alpha 降序选股, 行为一致。ML 包不保存 weights(feature_importance 仅可解释性参考)。

### 6.2 真实缺口(需对齐)

| # | 缺口 | 影响 | 修复 | 状态 |
|---|---|---|---|---|
| 1 | `score_stocks_by_package` 对 **technical_ts** 因子未做 `ts_rank_normalize`(训练端 B1 先分位化再入截面) | 包里含 SMA/EMA/价格水平因子时, 晨报选股被绝对价格量纲主导, 与训练端口径不一致 | 消费端对 technical_ts 因子补滚动分位后再预处理(按因子元信息判断, 与评价侧 `resolve_ts_window`/`ts_rank_normalize` 同口径); **ts_normalize_window 随包保存, 消费端优先用包内训练窗口** | ✅ 已修复 (P1-3 + 2026-08-15 补强, 见 7.12) |
| 2 | **signal** 因子在消费端按连续因子 zscore(评价端走 F2 方向得分独立轨 + 0.5 系数叠加) | 含信号因子的包, 晨报口径与评价略有差异 | 消费端对 signal 因子按方向转得分(0/±1 → direction 加权)后并入综合 | ✅ 已修复(2026-08-15): `score_stocks_by_package` 分离 signal 因子走 `_signal_score_panel` 方向得分独立轨, 混合时与连续综合按 0.5 叠加, 仅信号直接取方向得分(见 7.13) |
| 3 | 消费端预处理 `_preprocess_cross_section(winsorize_n=3.0)` vs 训练端 B1 去极值+中位数填充 | ML 预测特征分布与训练偏移 | 核对统一两端去极值/缺失口径 | ✅ 已一致: 两端同一函数同参数(`winsorize_mad(3.0)`=median±3×1.4826×MAD + fillna(median) + 中性化 + zscore, 见 7.12) |

> 验证: 用同一因子包分别跑"多因子评价 B2"与"晨报 score_stocks_by_package", 对比同一截面 Top-N 与 alpha 排序是否一致。
