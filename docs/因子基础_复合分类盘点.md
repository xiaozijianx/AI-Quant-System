## 一、分类规则(用户确认)

### 基础因子
金融学上**有明确定义、或有独立明确语义**的指标。**即使内部使用了算子 / 时间系数, 也算基础因子**, 因为它的语义不依赖某个事后附加的时间周期。

典型: MACD(内部用了 EMA12-EMA26)、RSI、KDJ、布林、K线形态、动量、波动率、量比、OBV、基本面指标、Barra 风格因子、缠论、微观结构指标等。

### 复合因子
两类:
1. **时间平均 / 加权 / 平滑派生量**: 建立在已有基础因子或原始字段之上, 额外施加时间平均、加权、平滑得到。**把附加的时间周期拿掉就失去意义**。
   例: 60日均收盘价 = 收盘价 + 时间平均; EMA 单均线; 动量斜率; 乖离率。
2. **多基础因子 + 复杂算子 + 加减运算组合**: 即使能找到一个可解释的含义, 也算复合因子。
   例: qinghua/day2_M 的 5 个 WQ_* 因子; 各交叉类因子(动量波动交叉等); 龙头总分。

### 判断口诀
> **"这个因子的意义是否依赖一个事后附加的时间周期?"**
> - 依赖(时间平均/加权/平滑) → **复合**
> - 不依赖(有独立指标语义) → **基础**

## 一·五、因子粒度(归并规则) —— 用户补充的关键认知

**"因子"的正确粒度 = 一个指标类型,而不是"指标类型 × 周期"。**

核心判断: **该指标的金融学解释是否依赖特定周期?**

### 周期无含义类(解释不依赖周期 → 不同周期归并为同一基础因子)
金融学解释换任何周期都成立, 周期只是该因子的**可配置参数**。
- 例: `ret_1d/3d/5d/10d` → 1 个"收益率"; `momentum_5d/10d/20d/60d` + `MOM_1M/3M/6M` → 1 个"动量"
- `hist_vol_10d/20d/60d` + `VOL_20/60` → 1 个"波动率"
- `amplitude_5d/10d` → 1 个"振幅"; `vol_ratio_5d/10d` → 1 个"量比"
- `rsi_14/rsi_6/RSI_14` → 1 个"RSI"; `ma5_bias..ma60_bias` → 1 个"乖离率"

### 固定参数类(解释绑定固定参数 → 单一固定因子, 不按周期归并)
参数变了, 指标语义就变味。
- 例: MACD(EMA12/26/DEA9)、KDJ(9/3/3)、ATR(14)、CCI(14)、威廉(14)

### 判断口诀
> **"换一个周期, 这个指标还是不是同一个金融概念?"**
> - 是 → 属于同一基础因子, 周期作为参数, 应**归并**
> - 否(MACD 换成 24/52 就不再是标准 MACD) → 单一固定因子

> 注意: 归并只针对"基础因子"粒度。复合因子(时间平均派生/多因子组合)仍按原规则, 不参与周期归并。

## 一·六、因子基类(factor_base)设计 —— 用户最终确认的存储方案

**核心思想(用 Python"基类"比喻):**
收益率这类"天然与时间绑定"的指标, 剥离周期就不存在, 所以它不是一个"完整的具体因子", 而是**因子基类(base)**。具体因子 = 基类 + 周期参数生成。

### 基类也分两类
- **必须指定周期才生效的类型**(periodic): 如 `returns`(天生依赖周期, 不给 period 无法计算)
- **本身就是基础因子的类型**(fixed): 如 `macd`(固定参数, 调周期没有意义, 它就是单一基础因子)

> **2026-08-10 更新**: 基类概念最终调整为 -- 所有基础因子都同时登记在因子表和基类表中(因子表 base_id 指向基类表中对应的记录), 加上需参数才能成为因子的参数化基类(RSI/ADX/MACD等)。
> 基类不再区分"基础实例/复合实例", 前端基类区块改为可搜索下拉, 联动分类筛选。
> 详见 [因子库优化目标任务.md](./因子库优化目标任务.md)。

### 数据结构(先落盘, 暂不写代码)
```
factor_base(因子基类表)              -- 定义指标类型 + 计算方式模板 + 是否需要周期
  ├─ returns  type=periodic : pct_change(period), 不指定 period 无法计算
  ├─ momentum type=periodic : ROC(period)
  └─ macd     type=fixed    : EMA(12)-EMA(26), 本身即一个独立基础因子, 无周期参数
```

### factor_library(具体因子表) —— 自包含, 所有具体因子都在这张表
基础因子实例 + 复合因子**都存放于此**, 是否基础因子用字段标注, 不依赖基类分类。
字段:
- `factor_id`: 唯一标识(如 ret_5d / macd_dif / WQ_MOMENTUM_DECAY)
- `base_id`: 关联基类, **主要用于显示归并 / 构造生成**(不参与计算还原)
- `dependencies`: 依赖哪些因子(数组/JSON), 复合因子依赖多个基础因子
- `formula`: **计算方式, 直接存, 自包含** —— 不靠基类组装公式还原
- 其他元数据: name / description / category / source 等

```
factor_library(具体因子表)
  ├─ ret_5d        base_id=returns,      dependencies=[],        formula="close.pct_change(5)"
  ├─ macd_dif      base_id=macd,         dependencies=[],        formula="EMA(12)-EMA(26)"
  ├─ momentum_5d   base_id=momentum,     dependencies=[],        formula="ROC(close,5)"
  └─ WQ_MOMENTUM_DECAY  base_id=wq_comp, dependencies=[momentum_5d, ...], formula="<自包含完整表达式>"
```

### 关键约定
1. **不同周期分开存、不合并**, 但通过 `base_id` 索引到同一基类, 表达"同源"(显示归并)。
2. **具体因子表自包含计算方式**(formula), 复杂复合因子**不通过基类组装公式还原**, 直接查表即可得。
3. **`base_id` 只用于显示层级与构造生成**, 不承担计算还原职责。
4. **依赖用 `dependencies` 列表达**(替代独立依赖表), 复合因子依赖多个基础因子。
5. 前端(后续设计): 按基类展示层级(基类 → 各周期实例 → 复合因子依赖链), **本期先不做前端, 设计保留在此文档**。

### 为什么不用"物理合并" / 独立依赖表
- 不合并: 保留周期精度, 未来可扩充 20 日等新周期。
- 不设独立依赖表: 复合因子也是具体因子, 用 `dependencies` 一列即可表达依赖, 避免过度设计。

## 五、现状问题(盘点发现)

1. **数据库没有"基础/复合"维度**。`factor_library` 表只有 `category`(用途分类)和 `is_custom`(是否自定义), 没有 `factor_type` 字段。
2. **前端判断逻辑过粗**。`factor.html` 的 `originType()` 仅靠 `category==='composite'` 判断复合, 结果只有 5 个 qinghua WQ_* 因子被识别为复合, **其余 41 个复合因子(均线、乖离、交叉、斜率等)全部被错标为"基础"**。
3. **复合因子的数据来源需要补全**: 当前 `factor_library` 中复合因子只有元数据, 没有统一的计算实现(见"融合"待办)。

## 六、后续待办(供后续继续, 防止上下文遗忘)

### 第 1 步: 数据库加"因子类型"维度
- 在 `factor_library` 增加字段 `factor_type`(VARCHAR): `basic` / `composite` / `custom`
- 按本盘点结果, 用脚本批量回填 182 基础 + 41 复合
- `is_custom=True` 的仍归 `custom`(用户构造)

### 第 2 步: 前端改造
- `originType()` 改为读 `factor_type`, 不再靠 `category='composite'` 猜
- 来源类型筛选(基础/复合/自定义)与明细均基于 `factor_type`

### 第 3 步: 评估配置标准化(对应"性能与标的/时段有关")
- 新增"评估配置"概念 = 股票池 + 起止日期 + 调仓周期 + 分层数
- `factor_metrics` 关联到某个评估配置, 使同一因子的不同标的/区间性能可区分、可追溯

### 第 4 步: 因子融合(重点, 非简单拼接)
- 先盘点各 case 对因子的**构造方式 / 评价方式 / 性能构造方式**, 及其设计原因
- 画出各 case 处理逻辑的关系图, 找出共性 / 重叠 / 冲突
- 设计统一的计算与评价框架, 再有序融合
- 因子层: 按统一分类标准合并、去重(几百个中有重复)
