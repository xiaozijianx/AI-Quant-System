## 2. 工作流主线

### 步骤1 因子库(定义与存储)
`POST /init` → `factor_init.run_init()`:建表 → 导入因子 → 注册基类 → 前缀规则+SPECIAL_CLASSIFY 回填 factor_type/base_id → 中文分类回填。
支持 `POST /save`(自定义表达式因子,自动解析标签)与 `POST /generate`(基类+周期生成实例,如 bias_20)。

### 步骤2 因子构建(表达式引擎)
- 表达式形如 `-1*ts_Decay((ts_Decay(Close,10)-ts_Decay(VWAP,10))/VWAP*(High-Low),40)`
- 算子:ts_*(时序 30+)、cs_*(截面 4)、ta_*(Talib 指标/61 种 CDL 形态)、基类调用(rsi(14)、FN(roe) 财务引用)
- 安全:标识符白名单 + 危险关键字过滤 + `eval(expr, {"__builtins__": {}}, namespace)`(factor_engine.py:3441-3588)
- `POST /construct` 试算(返回最新截面值 + 单截面近似 IC);`POST /save` 入库

### 步骤3 因子挖掘
- `POST /mine_svd`:收益率矩阵 SVD 隐因子(奇异值/方差解释/暴露)
- `POST /mine_ml`:XGBoost 特征重要性(注意:样本=每股一条,是截面重要性不是时序挖掘)

### 步骤4 单因子评价(`POST /evaluate`,按类型分四条支线)
```
classify_factor_type(factor_info)
 ├─ pattern   → evaluate_pattern_factor: 信号频率/命中率/条件收益(离散信号不做IC)
 ├─ financial → 调仓日对齐财报可用日(report_date+120d), run_ic_timeseries_panel
 ├─ single池  → run_single_ic_timeseries: 单股时序IC
 └─ technical → run_ic_timeseries_panel(滚动截面IC/IR/胜率)
                + run_layered_backtest(单截面分层)
                + PerformanceWithCost(清华, cost=0.2%, delay=2天)
                + GetQuantileRet(分位数年化收益)
```
有效性分级(IC均值/IR 阈值)→ 持久化 factor_metrics + factor_eval_result → 前端切页恢复。

### 步骤5 多因子分析(两条路径并存)
- **旧路径 `POST /synthesize`**(Tab5 组合优化):逐调仓日 calc_basic_factors → 等权/当期IC加权/Lasso → Top-N 等权组合净值(无成本)
- **新路径 分阶段 B1/B2**(Tab6 多因子分析):
  - B1 `POST /multi_prep`(与合成方式无关,内存缓存 prep_id):
    单因子预评价 → 技术因子逐截面清洗(3σ MAD + 中位数填充 + 回归中性化)→ 清洗诊断 → 缓存
  - B2 `POST /multi_synth`(切合成方式复用 B1):
    全历史IC筛选(|IC|/非空率/覆盖率)→ 跨期平均Spearman相关去冗余(阈值0.8)→ 方向(设计为walk-forward)→ 10种合成方式 → 组合IC时序 → 分层(多期平均)→ Top-N回测(含换仓成本,基准=全体等权)

### 步骤6 批量分析与因子包闭环
- 顶部"批量性能分析":`POST /batch_evaluate`(仅覆盖 12 个硬编码因子,与 Tab4/5 的公式引擎是两套计算体系!)
- 因子包:`POST /package` 保存"最终使用参数"(全历史重训 ML/PCA 落盘)→ 晨会 `morning_brief/graph.py:283-305` 通过 `score_stocks_by_package` 复用选股 → 闭环出口

## 3. 计算与处理方式逐环节评估

### 3.1 做得合理的地方 ✅
1. **B1/B2 分阶段 + 缓存**:预处理与合成方式解耦,切换合成方式不重跑数据准备,工程上正确。
2. **B2 主循环是严格 walk-forward**(factor_engine.py:2484-2660):ML 只用截至当期之前的历史训练、IC 权重用历史 ic_lookback 期、Markowitz/Optuna 权重用历史截面、自动方向用历史 IC——没有未来函数。
3. **预处理管线规范**:3σ MAD 去极值 → 分组哑变量+ln(市值)回归取残差 → z-score(996-1025, 1537-1572),与主流做法一致。
4. **财务数据对齐意识好**:report_date+120d 作为可用日、asof 对齐+ffill(严格不过未来)、财务因子调仓对齐财报期。
5. **评价差异化**:技术/形态/财务/单股四种因子各有适配的评价方法,而不是一刀切 IC。
6. **表达式引擎有安全沙箱**(白名单+清空 builtins)。
7. **评价结果持久化 + 因子包复用闭环**(晨会消费因子包)。
8. PerformanceWithCost 延迟 2 天交易、成本 0.2% 单边,Top-N 回测有换仓成本、有基准对照。

### 3.2 高优先级问题 🔴(必须修)

1. **因子方向(direction)在多因子合成中全部失效**
   - `factor_library.direction` 存字符串("positive"/"negative"/"neutral")(factor_db.py:52)
   - `routes/factor.py:1416-1418` 与 `:1696-1699`:`int(d) if d in (1,-1,0) else 1` —— 字符串永远命中 else → **全部变成 1(正向)**
   - `_auto_direction` 中 `direction_map.get(fid,0)!=0` 永远为真 → walk-forward 自动方向**永远被全 1 的手工方向覆盖**(factor_engine.py:1877-1878)
   - `_apply_direction`/`rank_score_synthesis` 只在 direction<0 时翻转 → 永不翻转(1991-1997, 1381-1386)
   - 后果:负向且公式未内嵌取负的因子(如 `atr_norm_14`=atr(14) 未取负、`hist_vol_10d` 等)在等权/rank/IC 合成中按正向参与;而公式内嵌负号的因子(REV_5D=reversal(5) 已取负、VOL_20=-volatility(20)、LIQ_20、TURN_20、BIAS_20)碰巧自洽 → **方向语义依赖公式写法,不一致**
   - 修复:构造 direction_map 时映射字符串 {"positive":1,"negative":-1,"neutral":0};neutral(0)让位给自动方向;统一约定 formula 不含方向、方向由 direction 字段负责。

2. **两套因子计算体系并存,同名因子结果不可比**
   - 体系A(Tab4/Tab5/Tab6-B1B2):factor_library.formula + 表达式引擎 `calc_factor`
   - 体系B(批量性能分析/旧 synthesize):`calc_basic_factors` 硬编码快照(仅 12 因子,factor_evaluator.py:41-64)
   - 同名因子差异实例:`MACD_DIF`:A=ts_MACD_DIF 原始值,B=dif/close 归一化(3863:3857);`ATR_NORM_14`:A=+atr(14)/close(未取负,方向靠失效的 direction),B=-atr/close(3850);`TURN_20` 两套都是量比(都错,见问题3)
   - 后果:因子库列表的 IC/IR 列(批量写入)与详情弹窗(公式引擎)数值口径不一致,批量只覆盖 12/300+ 因子
   - 修复:批量评估改为遍历 factor_library 可计算公式,复用 calc_factor/run_ic_timeseries_panel。

3. **"换手率"因子实现为量比**
   - `BASE_OPERATOR_MAP["turnover"] = ("ts_VolRatio", ["Volume"], 1)`(3364):Volume/Volume.rolling(n).mean(),是量比
   - 而数据源有真实 turnover_rate 字段(backtest_data.py:86-106 已加载、_build_field_dfs 有 "Turnover":"turnover" 映射)
   - TURN_20/turnover_ratio/turnover_change_5d 名称带"换手"但实为量比,经济含义错误;流动性/换手因子结论会误导。

4. **`/synthesize` 的 ic_weighted 用当期 IC 加权(前视)**
   - routes/factor.py:1167-1171 注释自认"简化: 用当期 IC 做演示"——用未来收益算出的当期 IC 作为当期权重,标准前视
   - 与分阶段 B2 的 walk-forward IC 加权口径矛盾;建议废弃该路径或改为 walk-forward,统一到 B1/B2。

5. **股票池与中性化映射用"当前"信息(生存者/时点错配)**
   - `get_active_stock_pool`:按**当前近30天**成交活跃选股 + 全历史≥200天 → 排除退市股/次新股,回测历史存在生存者偏差(factor_evaluator.py:76-151)
   - 行业/板块映射来自 trade_stock_status **当前**分类,概念用**最新** trade_date 标签(stock_classify.py:66-74, 108)——历史截面的行业归属会被未来分类改写
   - 市值映射 = 最新总股本 × **当前价**(stock_classify.py:174-199)——历史截面中性化用当前市值,时点错配
   - 修复:引入点-in-time 成分(如沪深300历史成分)与历史行业/市值快照,至少在中性化时用截面当日市值。

6. **日K无复权处理(需先确认数据)**
   - load_daily_kline 直读 trade_stock_daily 的 close_price,xtdata 用 dividend_type="none"(backtest_data.py:84-106, 140)
   - 若 PG 表存的是不复权价:除权日收益率/动量/价格类因子全部失真。**需确认 trade_stock_daily 是否前复权**;若不是,必须引入 adj_factor 复权,否则所有价量因子评价不可信。

7. **Top-N 组合回测年化/夏普公式错误(高估约 21 倍/√21 倍)**
   - `_nav_metrics(nav_vals, n_periods)`(factor_engine.py:2844-2880)被 `_multifactor_topn_backtest` 以"每调仓期一个净值点"传入(2832-2833),即每期 = rebal_period(默认21)个交易日
   - 但 `annual = nav[-1]**(252/n_periods)-1` 把期数当"天"用,正确应为 `252/(n_periods×rebal_period)`;`sharpe = m/s*sqrt(252)` 应 × `sqrt(252/rebal_period)`
   - 后果:Tab6 多因子分析展示的 Top-N 年化收益高估约 21 倍、夏普高估约 √21≈4.6 倍,严重误导策略选择;基准同口径所以"相对比较"仍有效。旧 `/synthesize` 的年化口径反而是对的(routes:1204-1205)。

8. **阶段A(B2 开头)因子筛选用全样本 IC(样本内选择偏差)**
   - `synth_multi_factor_eval` 先用**全历史**截面 IC 做 |IC| 阈值筛选、相关去冗余(factor_engine.py:2452-2474),再进入 walk-forward 合成
   - 合成环节本身无前视,但"因子集的选择"用了全样本(含未来)信息 → 回测结果偏乐观,实盘换因子集可能失效。建议:筛选/去冗余也改为滚动(walk-forward 逐期决定因子集)或仅用训练窗内 IC。

### 3.3 中优先级问题 🟡

7. **PerformanceWithCost 方向是事后选择**:`dire` 用全样本因子收益符号(1160-1162),展示的夏普/年化是"事后最优方向",高估可交易性(清华原版特性,页面需标注);position 用标准化因子而非资金权重,成本/换手为近似。
8. **ML 合成"walk-forward"实际只训练一次**:`ml_model is not None` 后永不重训(factor_engine.py:2554-2560),首次攒够 100 样本训完即冻结,模型对后期市场陈旧;purged AUC 只反映首段数据。
9. **purged k-fold 的 gap 不足**:`gap=5 行` 远小于一期截面行数(约50-100),训练标签窗口(21日收益)与测试特征重叠 → AUC 偏乐观;且是顺序 holdout 而非真 purged k-fold(2198-2224)。
10. **逐股位置索引对齐错位**:`_cross_section_future_return`/`run_ic_timeseries_panel` 用首只股票日历的位置 `iloc[end_idx]` 取所有股票价格,停牌缺行/晚上市的股票位置与日期错位,且随停牌累积(1512-1534, 3157-3166)——取决于 PG 表停牌日是否存行,需验证。
11. **非空率筛选形同虚设**:factor_non_null 按"当期≥1个非空"折算期级比例,且 prep 已中位数填充 → 除整列 NaN 外几乎全 1,min_non_null=0.5 筛选失效(1905-1906, 2465)。
12. **Top-N 回测成本只算单边**:换仓 turn*cost 应为双边 2*cost(2813-2817);建仓期无成本;无涨跌停/停牌过滤(一字板不可成交未处理)。
13. **财务延迟 120 天一刀切**:Q1/Q2/Q3 季报实际披露远快于 120 天,统一延迟过度保守、降低信息时效(financial_data.py:82, 133);fin_Delay 用 shift(63 交易日)近似财报期(206-207)。建议按财报类型分级 lag 或使用真实公告日。
14. **`Turnover` 字段列名不匹配(表达式会炸)**:`_build_field_dfs` 映射 "Turnover"→"turnover"(3508),日K实际列名是 "turnover_rate"(backtest_data.py:106)→ 引用 Turnover 的表达式校验通过但 eval 时 NameError;PE/PB/ROE 同理在日K中不存在,白名单形同虚设。
15. **Lasso 因子包双重翻号**:保存包时 Lasso coef 未按方向翻转(2333-2344),`score_stocks_by_package` 线性路径又按 direction 翻转(3738-3750)→ 负方向因子的 Lasso 包实盘选股方向错误。
16. **多因子合成股票子集偏差**:`valid = pre.dropna(how="any")` 要求所选因子全部非空(2539),含财务/缺失因子时大量股票被静默排除,Top-N 可投集变化未披露。
17. **批量评估同步阻塞 1-2 分钟**,前端进度条是假的(注释自认,factor.html:2205-2208);应改为任务化/SSE 流式。
18. **前端功能 bug**:
    - 单因子弹窗分层累计收益图**永远空白**:`/evaluate` 的 layered_backtest 无 layer_cumret(factor_engine.py:1354-1358),渲染却需要它(factor.html:2471);返回该字段的 `/evaluate_single` 前端从未调用(死端点)
    - 历史恢复产生假 prep_id='restored'(factor.html:1997),点②合成必 400(routes:1766-1767)
    - Tab3 挖掘/Tab5 组合优化依赖 Tab2 维护的 stockCodes,直达报"请选择股票"
    - Tab4 一次只评 selectedFactors[0](2938),UI 却支持多选
    - toggleAll 用后端结果而非前端过滤后列表(2174-2176)
19. **eval 结果冲突键不含 rebal_period/n_layers**(factor_db.py:143):同因子不同调仓周期的评价互相覆盖;get_eval_result 回退"任意最新一条"可能张冠李戴。
20. **多因子 prep 缓存是进程内存 OrderedDict**(上限20,无锁):多 worker 部署 prep_id 必失效;服务重启丢失;因子包保存依赖此缓存重算最终参数,失效时静默回退前端参数。
21. **eval_result 大 JSONB 无清理策略**,不同配置版本累积,表无限膨胀。
22. **代码重复**:股票池构建/中性化映射/单因子预评价在 evaluate、multi_factor_eval、multi_prep 重复三份;direction_map 构造重复两处(同 bug 重复)。
23. **数据质量**:CDL_HIGHWAVE 公式误写为 ta_CDLHIKKAKE(factor_init.py:723);LIQ_20 base_id 指向 "amount" 而非 liquidity 基类(1041);ID 命名 snake/UPPER/厂商前缀混用。

### 3.4 低优先级问题 🟢
24. `/construct` 的 IC 是单截面近似(最新截面 vs 20日收益),标签易误导。
25. 因子分类依赖脆弱的前缀规则 + 60 余条手工 SPECIAL_CLASSIFY 兜底。
26. `mine_ml` 的 r2_score 是训练集 in-sample;n_samples=股票数(截面,非时序)。
27. 财务因子 rebal_period 前端上限 60 与后端强制 >=63 冲突,输入被静默改写。
28. save_eval_result 静默吞异常,历史恢复失败难排查。
29. 表达式引擎无长度/复杂度上限,`pow`/`**` 可构造超大整数(DoS 面);`cs_Zscore` 无 std=0 防护(112);`cs_Mean` 名不副实(实为去均值);CDL 形态双重注册、死代码(_FN_CACHE 等)。

## 4. 改进建议(按优先级)

| 优先级 | 事项 | 影响 |
|---|---|---|
| P0 | 修 direction 字符串→整数转换 + 统一 formula 不含方向 | 多因子合成方向正确性 |
| P0 | 修 Top-N 回测年化/夏普公式(252 应除以期数×调仓天数) | 指标绝对值可信度 |
| P0 | 确认/引入日K复权(adj_factor) | 所有价量因子可信度 |
| P0 | 批量评估改走公式引擎,统一两套计算体系 | 结果可比性、覆盖 300+ 因子 |

## 5. 建议的长期工作流(供页面设计参考)

```
因子库(定义, formula 统一不含方向)
  → 构建/挖掘(表达式沙箱; 挖掘结果需回填入库)
  → 单因子评价(按类型: technical IC时序+分层+PWC / financial 财报对齐 / pattern 信号 / single 时序IC)
  → 多因子分析(仅技术类: B1 统一预处理 → 筛选|IC|+去冗余+方向 → B2 walk-forward 合成×10 → 组合IC/分层/Top-N回测含双边成本)
  → 因子包(全历史定参 + 模型落盘)
  → 晨会/实盘消费(score_stocks_by_package)
```
每一步的结果持久化键必须包含全部影响口径的参数(调仓周期/分层数/中性化/池)。
