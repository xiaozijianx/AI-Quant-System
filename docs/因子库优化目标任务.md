## 任务一: 因子筛选与清理

### 目的
对库中 240 个因子逐一审核, 清理无效因子, 修复分类矛盾。

### 背景
因子来源于各个 CASE 工程, 部分因子存在以下问题:
1. **不是因子**: 某些信号/标记被误录入为因子(如"MACD信号"是交易信号, 不是因子)
2. **基类矛盾**: 某些因子被标记为基础因子(factor_type=basic), 但 base_id 指向另一个基类, 违反"基础因子在基类表中应有对应记录, base_id 指向该记录"的规则
3. **语义不合理**: 某些因子的金融含义不成立, 或不适合用于股价性能评估

### 已发现的问题

#### 问题1: MACD 系列(4个因子)

| factor_id | 名称 | factor_type | base_id | 问题 |
|-----------|------|-------------|---------|------|
| macd_dif | MACD_DIF | basic | macd | 基础因子的 base_id 应指向基类表中自己的记录, 不应指向 macd |
| macd_dea | MACD_DEA | basic | macd | 同上 |
| macd_hist | MACD柱状图 | basic | macd | 同上 |
| macd_signal | MACD信号 | composite | macd | **信号不是因子**, 应移除 |

**分析**:
- MACD_DIF、MACD_DEA、MACD柱状图: 可以作为独立的基础因子, 但如果它们是基础因子, 就应在基类表中有对应记录, base_id 指向各自的基类记录(dif/dea/hist), 而非指向 macd
- 另一种理解: 如果把 MACD 视为一个基类(需参数才能生成), 那么 DIF/DEA/HIST 是该基类的具体实例, 应为复合因子, base_id=macd
- MACD信号: 这是交易信号(金叉/死叉), 不是数值因子, 不应存在于因子表中

**待决策**:
- [ ] DIF/DEA/HIST 是基础因子(在基类表中有独立记录) 还是复合因子(base_id指向macd基类)?
- [ ] MACD信号: 直接删除, 还是标记为非因子?

#### 问题2: 缠论系列(7个因子)

| factor_id | 名称 | 问题 |
|-----------|------|------|
| chan_buy1 | 一类买点 | 买点是交易信号, 不是因子 |
| chan_buy2 | 二类买点 | 同上 |
| chan_buy3 | 三类买点 | 同上 |
| chan_sell1 | 一类卖点 | 同上 |
| chan_sell2 | 二类卖点 | 同上 |
| chan_sell3 | 三类卖点 | 同上 |
| chan_divergence | 背驰 | 可能是因子, 需确认 |

**分析**: 缠论的买卖点是结构信号(0/1或离散值), 不是连续数值因子, 不适合用于因子评价(IC/分层回测等)。背驰如果能量化为连续值, 可能保留。

**待决策**:
- [ ] 缠论买卖点: 整体移除, 还是标记保留?
- [ ] 背驰: 是否可以量化为连续因子?

#### 问题3: 其他需审核的因子类型
- 微观结构因子(OFI, large_ratio等): 来源于tick级数据, 日K级无法计算, 是否保留?
- 龙头因子(dragon_score等): 是否适合作为选股因子?
- Talib形态因子(68个CDL_*): 都是0/1离散值, 能否用于IC评价?

### 执行步骤
1. 逐因子审核: 结合 origin(来源CASE) + formula + category 综合判断
2. 标记问题因子: 分为"删除"和"修正"两类
3. 修复基类矛盾: 确保基础因子在基类表中有对应记录且 base_id 指向该记录, 复合因子 base_id 指向其构成基类
4. 更新数据库: 删除无效因子, 修正错误标签, 同步基类表

### 产出
- 因子审核清单(每个因子的判定结果: 保留/修正/删除 + 理由)
- 清理后的因子库(预期保留220-235个因子)

## 任务二: 各CASE因子处理逻辑调研

### 目的
摸清各 CASE 工程对因子的计算方式、评价方式、处理流程, 为构建统一的因子评价系统提供依据。

### 背景
当前因子评价系统存在两个割裂的路径:
1. `calc_basic_factors()`: 硬编码了12个因子的计算, 只支持这12个因子的评价
2. `evaluate_expression()`: 能解析表达式(如 `ts_Decay(Close, 10)`), 但只用于因子构建tab, 未接入因子评价

不同类型的因子(价量/技术指标/基本面/缠论/Talib形态等)的计算方式和评价方式可能不同, 需要一个能根据因子类型自动匹配计算和评价方法的统一框架。

### 调研范围

#### 需要调研的 CASE 工程

| CASE工程 | 因子类型 | 调研重点 |

| CASE-AI量化系统/ml_strategy | 价量/动量/波动/K线形态 | feature_engine.py 的计算逻辑 |
| CASE-AI量化系统/morning_brief | 基本面/动量 | factor_runner.py 的因子处理 |
| CASE-C-多因子选股 | 动量/反转/波动/流动性 | factor_lib.py 的计算与评价 |

| Barra 风格因子 | 风格暴露 | Barra 因子的计算逻辑 |

#### 每个CASE需要回答的问题
1. **因子计算方式**: 用什么数据(OHLCV/财务/tick)? 怎么算(Python函数/Talib/表达式)?
2. **因子评价方式**: 是否做了IC/分层回测/多空收益? 评价周期和参数?
3. **因子预处理**: 是否做了去极值/标准化/中性化? 方式是什么?
4. **因子组合方式**: 是否有多因子组合? 等权/IC加权/回归?
5. **数据频率**: 日K/分钟K/tick? 是否支持多频率?
6. **特有功能**: 该CASE有没有其他CASE没有的特殊处理?

### 执行步骤
1. 逐CASE阅读代码, 按上述问题整理
2. 汇总各CASE的因子处理能力矩阵
3. 识别功能重叠和功能缺口
4. 设计统一框架: 因子类型 -> 计算方式映射 + 评价方式映射

### 产出
- 各CASE因子处理能力对比矩阵
- 因子类型-计算方式-评价方式映射表
- 统一因子评价框架设计草案

   - `calc_basic_factors()`: 硬编码12个因子, 库中235个因子无法评价
   - `evaluate_expression()`: 支持ts_*/cs_*算子, 但只用于因子构建tab, 未接入评价

   - 表达式引擎不支持Talib函数(ts_RSI/ts_MACD/ts_ADX等), 无法评价技术指标因子

5. **实施路径**: 优先扩展表达式引擎新增ts_RSI/ts_MACD等Talib封装 → 为235个因子编写标准formula → 改造评价接口

## 任务三: Formula 表达式体系设计

### 目的
设计 `formula` 字段的标准格式, 使其成为因子计算的单一数据源: 读库中的 formula 即可计算因子值。

### 背景
当前 formula 字段的问题:
- 大部分是文字描述(如"个股Beta vs 市场"), 不可执行
- 少数看似表达式(如"close.pct_change(1)"), 但评价引擎不支持
- 评价系统不读 formula 字段, 而是用硬编码函数

### 设计目标

#### 1. 因子计算的可执行表达式
formula 字段应存储评价引擎能解析和执行的标准表达式:
```
# 价量因子
ts_PctChange(Close, 1)          -> ret_1d
ts_PctChange(Close, 5)          -> ret_5d
ts_RSI(Close, 14)               -> rsi_14
ts_MACD(Close, 12, 26, 9)[0]    -> macd_dif
ts_MACD(Close, 12, 26, 9)[1]    -> macd_dea
ts_MACD(Close, 12, 26, 9)[2]    -> macd_hist
```

#### 2. 不同类型因子的表达式方案

| 因子类型 | 表达式方案 | 示例 |
|----------|-----------|------|
| 价量/动量/波动 | 算子组合 | `ts_PctChange(Close, 5)` |
| 技术指标(RSI/MACD/KDJ) | 内置函数 | `ts_RSI(Close, 14)` |
| Talib形态(68个CDL) | Talib函数封装 | `ta_CDLHAMMER(Open, High, Low, Close)` |
| 基本面因子 | 字段引用 | `FN(roe)` |
| 估值因子 | 组合表达式 | `Close / FN(eps)` |
| Barra因子 | 需特殊处理 | 回归暴露, 可能需要独立函数 |
| 缠论因子 | 需特殊处理 | 结构识别, 可能需要独立函数 |
| 微观结构 | 需特殊处理 | tick级数据, 可能需要独立函数 |

#### 3. 自定义复合因子的表达式生成
用户通过"基类 + 周期 + 参数"构造新因子时, 系统自动生成可执行表达式:
```
基类: rsi (参数化, type=periodic)
周期: 21
生成表达式: ts_RSI(Close, 21)
存入 formula: ts_RSI(Close, 21)
```

#### 4. 评价引擎改造
- 评价接口读取 factor 的 formula 字段
- 根据表达式类型选择计算引擎(算子引擎/Talib引擎/财务引擎)
- 计算因子值后执行IC/分层回测/多空收益评价

### 待设计问题
- [ ] 表达式DSL的函数清单(支持哪些函数?)
- [ ] 多返回值函数怎么处理(如MACD返回DIF/DEA/HIST)?
- [ ] 基本面因子如何引用财务数据?
- [ ] 不适合表达式化的因子(缠论/微观结构)如何处理?
- [ ] 表达式校验机制(防止无效表达式)?

### 执行步骤
1. 盘点现有 `evaluate_expression` 支持的算子, 确定需要扩展的函数
2. 设计表达式语法规范(函数名/参数/返回值)
3. 为240个因子逐类型编写标准表达式
4. 改造评价引擎: 读formula -> 解析 -> 计算 -> 评价
5. 联调验证: 表达式计算结果与原始代码一致

### 产出
- 因子表达式语法规范
- 240个因子的标准表达式清单
- 改造后的统一因子评价引擎
