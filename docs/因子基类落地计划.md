## 一、背景与目标

用户确认采用 **"分表存储 + 基类索引归并"** 方案处理因子分类:
- 不同周期的因子(如 ret_1d/3d/5d/10d)**分开存、不合并**
- 通过**因子基类 factor_base** 归并表达"同源"(收益率 = 基类 returns 的不同周期实例)
- 具体因子表**自包含计算方式**, 复合因子用 `dependencies` 表达对基础因子的依赖
- 前端按"基类 → 各周期实例 → 复合因子依赖链"展示层级

本计划的目标: 在现有前后端框架上, 落地 factor_base 及相关字段, **不破坏已导入的 223 个因子数据**。

## 三、落地步骤

### 步骤 1: 数据库表结构调整(factor_db.py 的 init_tables)

1. **新增 `factor_base` 表**(基类表):
   ```
   factor_base (
     base_id      VARCHAR(50) PRIMARY KEY,   -- 如 returns / momentum / macd
     name         VARCHAR(200) NOT NULL,      -- 基类中文名
     type         VARCHAR(20) NOT NULL,       -- periodic(需指定周期) / fixed(固定参数, 本身即基础因子)
     formula_template TEXT,                   -- 计算方式模板(含占位符, 仅参考, 不用于组装还原)
     description  TEXT,
     is_active    BOOLEAN DEFAULT TRUE
   )
   ```

   - `base_id VARCHAR(50)` —— 关联 factor_base, 用于显示归并 + 构造生成

## 七、复合因子formula基类实例化重构(2026-08-11)

> 目标: 复合因子的 formula 不再直接写运算符逻辑, 统一改为 **基类实例** 形式(如 `rsi(14)`/`momentum(10)`),
> 由引擎 `BASE_OPERATOR_MAP` 递归展开为算子在 `evaluate_expression` 中计算, 实现"基类+参数+算子"组装。

### 引擎(base_engine)扩展
- `BASE_OPERATOR_MAP` 覆盖全部 30 个基类(periodic + fixed), 新增 `open/high/low/close` 4 个基础行情基类(恒等变换 `ts_Identity`)
- 基类实例可调用: `_make_base_callable` 把 `基类(参数)` 展开为 `算子(字段面板..., 参数)`

### 复合因子formula改写(76个)
- 可映射为基类实例的复合因子全部改写(技术/量价/动量/波动/均线/RSI/ADX等), 用 `returns(1)`/`momentum(5)`/`bias(20)`/`atr(14)`/`sma(20)`/`rsi(14)` 等
- MOM_1M/3M/6M 原formula为 `ts_PctChange`(收益率语义), 基类由 momentum 修正为 returns, 保证数值完全一致
- **2026-08-11 追加**: WQ_* 复杂因子与 LIQ_20 也改写为基类实例形式, 其原子单元字段(Close/High/Low/Volume/VWAP/Value/IdioRet/TotalRet/Amount)全部注册为基类, formula 用 `close()`/`vwap()`/`volume()`/`idioret()` 等基类实例引用
- **不改写**(描述性非公式): 仅 SVD_HIDDEN(主成分分解 R=B*F+e)
- 新增基类: open/high/low/close(最基础行情字段) + volume/amount/vwap/value/idioret/totalret(量额均及派生字段, 共10个, 供WQ等量价因子作为底层单元)

### 验证
- `run_init` 幂等执行成功: 244 因子 / 205 基类, basic=168 / composite=76
- 75 个复合因子全部可用真实日K计算, 仅 SVD_HIDDEN(描述性)除外
- 逐因子对照: 改写后 formula 与原 ts_* formula 计算结果 **maxdiff=0, 完全一致**(MOM 修正后同样完全一致)
- WQ/LIQ 改写后与原始裸字段形式 **maxdiff=0, 完全一致**(14个因子逐一核对)

### 2026-08-11 递归机制复核(对照用户原则)
- 原则: 复合因子不直接计算, 通过查询基类表得知依赖的基类/算子/周期, 向上迭代拆分到基础因子后代入参数递归计算。

### 2026-08-11 两处系统性修正(严格对齐 + 字段基类登记为基础因子)

#### 修正一: base_id 与 formula 严格对齐(全库扫描 17 个不一致因子清零)

**问题**: 部分复合因子的 base_id 标注了 formula 中"并未实际调用"的基类(如 WQ 因子标了 volume_ratio/volatility/price_volume_corr, 但公式实际只调用 close/high/low/volume/vwap 等原始字段), 导致"读 formula 递归拆解"时 base_id 与公式对不上。

**原则**: base_id 必须 **严格等于 formula 中实际调用的基类实例集合**。递归拆解是照 formula 进行的, base_id 是公式各层基类实例的索引, 二者必须一一对应。

**修正明细(17 个)**:

| 因子 | 修正前 base_id | 修正后 base_id(formula 实际基类) |
|------|---------------|--------------------------------|
| WQ_PRICE_VOLUME | price_volume_corr,volume_ratio | close,vwap,high,low |
| WQ_VOL_ANOMALY | volume_ratio,volatility | volume,vwap,high,low |
| WQ_MOMENTUM_DECAY | momentum | close |
| WQ_VOL_PRICE_DECAY | volume_ratio,price_volume_corr | close,volume |
| WQ_IDIO_VOL | idioret,volume_ratio | idioret,volume |
| WQ_IDIO_AMPLITUDE_VOL | idioret,volatility,volume_ratio | idioret,high,low,close,volume |
| WQ_VWAP_AMPLITUDE | price_volume_corr,volume_ratio | vwap,close,high,low,volume |
| WQ_PRICE_AMPLITUDE_MEAN | price_volume_corr,volatility | close,vwap,high,low |
| WQ_VALUE_DECAY | volume_ratio,volatility | value,vwap,high,low |
| WQ_VOL_DECAY | volume_ratio,volatility | volume,vwap,high,low |
| WQ_HIGH_DECAY | volatility,price_volume_corr | high,vwap,low |

**验证**: 全库扫描 76 个复合因子, base_id 与 formula 实际基类实例 **0 个不一致**; base_id 悬空 0 个。

#### 修正二: fixed 字段基类同时登记为基础因子(原则落地)

**问题**: open/high/low/close/volume/amount/vwap/value/idioret/totalret 这 10 个 fixed 基类(无时间周期本身即是因子)此前只登记在基类表, 未登记为基础因子, 违反"基础因子一定是基类, 基类不一定是基础因子"的归属原则。

**原则**:
- **基础因子一定是某一基类的实例**; 但**基类不一定是基础因子**。
- 判别标准: 基类若**脱离时间周期就不能成为因子**(必须带周期/参数才有意义, 如 returns/momentum/RSI/ADX 等 periodic 类), 则只能做基类, 不能做基础因子。
- 基类若**无周期本身即是因子**(如收盘价 close、成交量 volume), 则该 fixed 基类必须是基础因子(base_id=自身)。

**实现**: 在 BASIC_FACTORS 新增"十四-bis、最基础行情字段因子"区块, 将 10 个 fixed 字段登记为基础因子, formula 用 `close()`/`volume()` 等基类实例形式, factor_id=base_id=自身, factor_type=basic。

**验证**: 10 个字段基类全部满足"在因子表(factor_type=basic, base_id=自身) + 在基类表"双登记; 18 个 periodic 基类无一错误地存在于因子表(QA 通过, 无"需周期却当基础因子"的情况)。

**附项修正**: `open` 基类调用 `open()` 原被表达式安全校验当作 Python 内置危险函数拦截, 已修正——`open` 作为合法基类名放行(danger 关键词列表动态剔除 BASE_OPERATOR_MAP 中的基类), 且 eval 环境 `__builtins__` 已清空、namespace 中 open 已被基类函数替换, 无安全风险。

- base_id 悬空 = 0, 76 个复合因子全部可递归计算, 10 个字段基础因子全部可计算
