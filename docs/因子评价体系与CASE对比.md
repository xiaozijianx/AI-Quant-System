# 因子评价体系与 CASE 对比

> 状态: **已落地** — 评价体系与融合结构已按本文档口径实现(technical/technical_ts/signal/financial 四类路由, 详见 [因子评价方式适配性审计与路由改造计划.md](./因子评价方式适配性审计与路由改造计划.md))
> 目的：梳理当前系统因子评价实现与三个 CASE（机器学习因子挖掘 / 网格与多因子 / 清华 day1_A）的对应关系、差异与融合结构，并明确"单股票池 vs 多股票池"下的评价语义。

---

## 一、三个 CASE 定位速览

| CASE | 维度 | 评价对象 | 核心指标 | 因子处理 | 定位 |
|---|---|---|---|---|---|
| 机器学习因子挖掘（茅台） | 单股票 × 单因子 | 时间序列 | 时序 RankIC | 原始值（多股才 MAD+Zscore+中性化） | 单因子快速检验 |
| 网格与多因子 | 多股票 × 多因子 | 截面 | 截面 RankIC / ICIR / 分层 Q1-Q5 | 原始值（无标准化） | 多因子筛选/选股 |
| 清华 day1_A | 多股票 × 单因子 | 全流程 | 夏普/年化/换手 + 分位数 + 调优 | 内部 `pn_TransNorm` | 单因子全流程 |

## 二、各 CASE 计算逻辑详解

### 1. 机器学习因子挖掘（茅台）
- 文件：`CASE-机器学习因子挖掘/1-贵州茅台因子分析.py`
- `calc_rank_ic`：对**单只股票**（600875.SH），把因子值时间序列与未来收益时间序列做 `spearmanr`。
- 这是**时序 IC**（同一标的不同时点，因子-收益相关性），不跨股票。
- 预处理 `preprocess_features`：MAD 去极值 + 中位数填充 + Z-score；`neutralize` 行业市值中性化（回归取残差）。多股工程用，单股脚本不调用。

### 2. 网格与多因子
- 文件：`CASE-网格与多因子/4-多因子评价框架.py`
- `calc_ic_series`：每个月末，对所有股票的因子值截面 vs 未来 20 日收益截面做 `spearmanr` → 月度**截面 IC 序列**，`ICIR = mean/std`。
- `quintile_backtest`：按因子值分 Q1(最小)~Q5(最大) 5 组，看各组平均收益与 Q5-Q1 价差。
- 因子值**不做任何标准化**直接用。

### 3. 清华 day1_A
- `PerformanceWithCost`：内部先 `pn_TransNorm`（截面排名→正态分位数）重标准化，再延迟 2 期、自动判断方向、扣交易成本、算夏普（`mean/std*15`）/年化（`mean*250`）/换手。
- `GetQuantileRet`：按截面分位点分 Q 组看年化收益单调性。
- 后续：Optuna 参数优化、因子相关性（CorrValue/CorrRet）、多因子合成（等权/夏普加权/Markowitz 等）。

## 三、当前系统融合结构（流程图）

当前 `/evaluate` 评价流程为**顺序流水线**：

```
① 选股票池(活跃/行业/概念/指数/自定义)
        ↓
② 加载日K面板 → calc_factor 按 formula 计算因子断面(factor_values)
        ↓
③ 因子类型分类(technical / pattern / financial)  → 差异化评价
        ↓
④ IC时序回测  ──来源: 网格多因子CASE──
   (每个调仓日取截面, MAD去极值+Z-score+可选中性化,
   算 截面Pearson IC + 截面Spearman RankIC + ICIR + 胜率)
        ↓
⑤ 分层回测  ──来源: 网格多因子CASE──
   (最新截面 Q1-Q5 分层收益 + 多空收益)
        ↓
⑥ PerformanceWithCost  ──来源: 清华day1_A──
   (原始factor_values → 内部TransNorm → 延迟2期 → 方向 → 扣成本
   → 夏普/年化/换手/策略收益曲线)
        ↓
⑦ GetQuantileRet  ──来源: 清华day1_A──
   (分位数年化收益, 看单调性)
```

即：**IC/分层沿用"网格多因子"的截面做法，PerformanceWithCost/分位数沿用"清华"的完整做法**。茅台的单股时序 IC 相当于 IC 时序中"单只票"的特例，未单独抽取。

## 四、关键结论：当前因子处理是否适合清华流程

**完全适合，且无需额外适配。**

1. 清华 `PerformanceWithCost` 内部会自己做 `TransNorm`（排名→正态分位数），这是**单调变换**，对极端值天然免疫。无论喂原始因子还是 MAD/Z-score 后的因子，它都会重新标准化，结果一致。
2. 当前 `/evaluate` 传给 PWC 的是 `factor_values`（calc_factor 的**原始断面**），与清华原始 day1_A 完全一致。
3. **差异注意**：当前 IC/分层会做 MAD+Z-score+行业中性化，但 **PWC 不做中性化**。这不是 bug，而是与清华一致——PWC 反映**不对冲行业/市值敞口的裸因子交易收益**，IC/分层反映中性化后的预测能力，两者互补。
4. 结论：无需担心"因子值被处理过"会破坏清华流程；只需理解 PWC 与 IC/分层是**两个互补视角**。

## 五、单股票池 vs 多股票池：截面还是时间序列？

| 场景 | 应使用的评价 | 原因 |
|---|---|---|
| 单股票池（1 只） | **时间序列 IC** | 截面只有 1 个样本，无法算相关性；时间序列 IC 以交易日为样本，可算 |
| 多股票池 | **截面 IC** + 分层 + PWC | 检验因子在横截面上的普适选股能力 |

- **截面 IC** 需要同一时点 ≥2 只（当前系统要求 ≥30 只）股票才能算相关系数。单股票池会直接无样本、返回空。
- **时间序列 IC**（茅台 CASE）是同一只股票、不同时点的因子值 vs 未来收益相关性，样本是时间点数量。
- **局限提醒**：单股票时间序列 IC 只检验"这只票上因子是否有效"，无法区分"因子本身有效"还是"该票恰好符合"。多股票截面 IC 才能衡量因子普适性。

## 六、单股模式（时间序列 IC）

- 股票池类型新增 **"单股模式(时间序列IC)"**，选中后输入单股代码（如 `600519.SH`）。
- 后端 `run_single_ic_timeseries`（来源: 机器学习CASE 茅台 `calc_rank_ic` 的滚动窗口版）：
  - 构造配对序列 `r_t = close[t+rebal]/close[t] - 1`；
  - 从最小预热期起，每 `rebal_period` 取一个时点，用过去 `window`(默认60) 个交易日的 `(因子值, 未来收益)` 对计算 Pearson IC 与 Spearman RankIC；
  - 得到 IC 时序序列 + IC均值/IC标准差/IR/RankIC均值/IC胜率/样本数。
- 前端评价页：单股模式下展示"单股时间序列IC评价"区块（IC 时序图 + 指标卡 + 有效性分级），与多股截面评价互斥显示。
- 单股模式不适用截面 IC/分层/PerformanceWithCost（同一时点仅一个样本）。
