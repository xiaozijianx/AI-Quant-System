# trade-plan 技能

生成或更新交易计划。本技能分四个阶段执行：数据收集（两个阶段）→ 综合判断生成 MD → 保存文件。

## 交易计划格式

**必须严格遵循 `template.md` 中定义的完整结构**，每个章节、标题、缩进都必须完全一致，否则解析器会出错。在生成交易计划之前，先使用 file_read 工具读取 `agent_config/skills/trade-plan/template.md` 文件对照格式。

**百分比的含义约定：**

| 场景 | 百分比含义 | 示例 |
|------|-----------|------|
| **买入（入场）** | **目标仓位的绝对比例**：本次买入量 = 目标仓位 × X%（固定基准，与当前持仓无关） | 目标仓位30%，写 `50%` = 本次买入目标仓位的50%（15%仓位）；写 `30%` = 本次买入9%仓位；分阶段买入写 `30%`+`30%`+`40%` = 100% 正好买满目标仓位 |
| **卖出（止盈/止损）** | **目标仓位的绝对比例**：本次卖出量 = 目标仓位 × X%（固定基准，与当前持仓无关） | 目标仓位30%，写 `30%` = 本次卖出目标仓位的30%（9%仓位）；分阶段减仓写 `30%`+`30%`+`40%` = 100% 正好卖完目标仓位；实际持仓不足时按实际持仓卖出 |

买入/卖出的百分比都是**相对于目标仓位的固定比例**，不是当前持仓或缺口的比例。系统执行时自动限制：买入不超过目标仓位上限，卖出不超过实际持仓。同一股票的多次买入/减仓条件百分比合计为 100% 时，即完成一整轮完整操作。

## Workflow

### 阶段A：收集基本面数据

加载以下技能（可并行加载，无需按顺序）：

- 加载 `position-info` 技能 → 获取当前持仓（股数、成本、价格、ATR）
- 加载 `stock-price` 技能 → 获取日 K 线数据（用于技术分析）
- 加载 `financial-analysis` 技能 → 获取财务指标（毛利率、ROE、负债率等）
- 加载 `read-pdf` 技能 → 如有年报/研报可阅读，获取基本面细节

> **精简流程（已有研报时）**：如果当前对话中已经生成了该股票的研报，直接执行下方的精简流程。

### 阶段B：收集板块与情绪数据

加载以下技能（可并行加载，无需按顺序）：

- 加载 `sector-rotation` 技能 → 获取该股票所属板块的轮动状态
- 加载 `concept-rotation` 技能 → 获取该股票所属概念的轮动数据
- 加载 `sentiment-analysis` 技能 → 获取舆情新闻和事件驱动信号
- 加载 `macro-sentiment` 技能 → 获取宏观情绪和市场整体风险偏好

另外，使用网络搜索工具（调用 MCP 网页搜索/提取工具）补充最新行业动态、公司新闻、市场预期等联网信息。

> **精简流程（已有研报时）**：如果当前对话中已经生成了该股票的研报，可以直接引用之前对话中的工具/技能调用结果或研报中的基本面数据、行业分析、板块轮动、情绪/舆情等结论，**无需重复加载 financial-analysis、sector-rotation、sentiment-analysis、macro-sentiment 等技能**。你只需要：
> 1. 加载 `position-info` 获取实时持仓
> 2. 加载 `stock-price` 获取最新 K 线（用于技术分析）
> 3. 调用 MCP 网页搜索/提取工具搜索最新动态（确保信息时效性）
> 4. 引用生成研报时获取的各类信息或研报中已有的分析结论，结合当前持仓和最新行情生成交易计划

> **交叉验证规则**：所有联网搜索得出的关键事实（股价数据、公告日期等）必须对照 MCP 搜索工具返回的真实结果与页面原文，确认可追溯来源后再写入交易计划；不得直接采用未经核实的搜索概述。财务指标/持仓数据必须来自本地 `financial-analysis` / `position-info` 数据，不得通过网络搜索获取。

### 阶段C：综合判断并生成交易计划

基于阶段A和阶段B收集的所有数据，综合判断以下内容，并**严格按照 `template.md` 中的格式**生成完整的 Markdown 交易计划。不确定格式时，再读一遍 `template.md` 对照。

**重要：生成的交易计划先展示给用户确认，不要立即调用 save_plan.py 保存。** 直接在对话框中输出完整的交易计划 Markdown 内容，让用户审阅。用户确认后，再执行阶段D保存。

**格式验证：** 在展示给用户之前，必须先用 validate_plan.py 验证格式是否正确。验证通过后再展示给用户：

先将生成的 Markdown 内容保存到临时草稿文件 `data/trading_plans/draft_{stock_code}_{trade_date}.md`（使用 `file_write` 工具），然后运行：

```bash
python agent_config/skills/trade-plan/scripts/validate_plan.py --file data/trading_plans/draft_{stock_code}_{trade_date}.md
```

**关键判断点：**

1. **操作建议**：买入/持有/卖出/减仓，并给出明确结论
2. **仓位管理**：根据当前持仓比例和市场判断，设定目标仓位区间
3. **入场计划**：是否入场？什么条件下入场？触发价是多少？
4. **出场计划（止盈）**：可设置多档止盈，**从下方参考条件中选择或自行判断**
5. **出场计划（止损）**：可设置多档止损，**从下方参考条件中选择或自行判断**
6. **风控说明**：单票最大仓位、单日最大亏损等
7. **判断逻辑**：综合基本面、技术面、板块、情绪的完整分析

**整手与资金约束（重要）：** 生成任何计划（入场/止盈/止损）前，必须结合当前股价与资金池，计算实际可交易手数（A股买卖须为100股整数倍）。若目标仓位下只能买/卖1-2手，则分阶段 `30%`/`30%`/`40%` 的减仓无意义，应简化为一次性整手操作（如直接写 `100%` 或按实际可成交手数），并据此设定触发条件与操作。

**条件块字段说明（必须严格遵守）：**

每个条件块（入场/止盈/止损）包含四个核心字段，**按以下顺序书写**：

**1. 触发条件（给人看）：**

`**触发条件**:` 用于前端展示给用户，必须使用以下格式之一：

| 类型 | 写法 | 解析结果 | 适用场景 |
|------|------|---------|---------|
| 浮盈止盈 | `**触发条件**: 浮盈高于 20%` | trigger_pct = +0.20 | 固定比例止盈 |
| 浮亏止损 | `**触发条件**: 浮亏超过 8%` | trigger_pct = -0.08 | 固定比例止损 |
| 价格突破 | `**触发条件**: 价格突破 ¥28.50` | trigger_price = 28.50 | 突破关键价位 |
| 价格跌破 | `**触发条件**: 价格跌破 ¥24.00` | trigger_price = 24.00 | 跌破关键价位 |
| 价格达到 | `**触发条件**: 价格达到 ¥27.80` | trigger_price = 27.80 | 到达指定价位 |

**2. 触发价（引擎信号价格）：**

`**触发价**:` 是引擎判断信号的唯一价格来源，必须写具体的价格数字，不能写百分比或文字描述。

| 正确写法 | 错误写法 |
|---------|---------|
| `**触发价**: ¥30.12（成本 ¥25.10 × 1.20）` | `**触发价**: 成本价 × 1.20` |
| `**触发价**: ¥24.00（双底支撑位 24.50 - 0.5×ATR 1.00）` | `**触发价**: 双底支撑位` |
| `**触发价**: ¥27.80（7/23 高点 27.75 + 0.05 缓冲）` | `**触发价**: 前高压力位` |

**3. 触发方向（引擎信号方向）：**

`**触发方向**:` 表示触发方向（向上/向下），是引擎判断信号的方向依据：

| 触发方向 | 含义 |
|---------|------|
| `向上` | 当前价 >= 触发价时触发 |
| `向下` | 当前价 <= 触发价时触发 |

**向上：** 当前价格突破触发价时触发；**向下：** 当前价格跌破触发价时触发。

**4. 操作（买卖方向 + 比例）：**

`**操作**:` 必须写明方向（买入/卖出）和具体比例（X%）。

| 正确写法 | 说明 |
|---------|------|
| `**操作**: 买入 50%` | 买入目标仓位的50%（固定基准，与当前持仓无关；系统自动限制不超过目标仓位） |
| `**操作**: 买入 100%` | 买入目标仓位的100%，正好买满目标仓位 |
| `**操作**: 卖出 50%` | 卖出目标仓位的50%（固定基准，与当前持仓无关；系统自动限制不超过实际持仓） |
| `**操作**: 卖出 100%` | 卖出目标仓位的100%，正好卖完目标仓位（实际持仓不足时按实际持仓清仓） |

**四字段分工：**
- `**触发条件**:` —— 前端显示用，给人看的（百分比或价格）
- `**触发价**:` —— 引擎信号价格（必须是具体价格）
- `**触发方向**:` —— 引擎信号方向（向上/向下）
- `**操作**:` —— 买卖方向 + 比例
- 引擎只比较 当前价 vs `**触发价**:`，按 `**触发方向**:` 判断触发，按 `**操作**:` 执行
- 例如：`**触发条件**: 浮盈高于 20%` + `**触发价**: ¥30.12（成本 ¥25.10 × 1.20）` + `**触发方向**: 向上` → 引擎比较 `当前价 >= 30.12` 触发卖出
- `**触发条件**:` 文字必须与 `**触发价**:`/`**触发方向**:` 一致，不能出现"触发条件说浮盈20%但触发价写错"的情况

**四个核心字段一览（引擎信号来源 = 触发价 + 触发方向 + 操作）：**

```
- **触发条件**: {浮盈高于 X% | 浮亏超过 X% | 价格突破 ¥X.XX | 价格跌破 ¥X.XX | 价格达到 ¥X.XX}（仅用于前端展示）
- **触发价**: ¥X.XX（计算依据，必须写具体价格，引擎信号来源）
- **触发方向**: {向上 | 向下}（引擎信号方向）
- **操作**: {买入/卖出} {X%}
```

**止盈条件参考（Agent 可从中选择，也可自行判断）：**

| 参考条件 | 触发条件写法 | 触发价计算 | 说明 |
|---------|------------|-----------|------|
| 固定比例止盈（系统默认+20%） | `浮盈高于 20%` | 成本价 × 1.20 | 最常用的止盈方式，适合绝大多数场景 |
| 固定比例止盈（+30%） | `浮盈高于 30%` | 成本价 × 1.30 | 强趋势股使用更高止盈目标 |
| 技术压力位止盈 | `价格突破 ¥27.80` | 取前高/颈线/平台压力位 | 反弹至关键压力位兑现 |
| 多档止盈（第一档） | `价格突破 ¥27.80` | 第一压力位 | 先兑现50%锁定利润 |
| 多档止盈（第二档） | `浮盈高于 20%` 或 `价格突破 ¥29.30` | 成本价×1.20 或 第二压力位 | 剩余持仓博取更高收益 |

**止损条件参考（Agent 可从中选择，也可自行判断）：**

| 参考条件 | 触发条件写法 | 触发价计算 | 说明 |
|---------|------------|-----------|------|
| 固定比例止损（系统默认-8%） | `浮亏超过 8%` | 成本价 × 0.92 | 最常用的止损方式，适合绝大多数场景 |
| ATR动态止损（1倍ATR） | `价格跌破 ¥23.95` | 成本价 - 1×ATR | 根据波动率动态调整，ATR从position-info获取 |
| ATR动态止损（2倍ATR） | `价格跌破 ¥22.75` | 成本价 - 2×ATR | 波动大时使用更宽的止损 |
| 均线趋势止损 | `价格跌破 ¥24.50` | MA20值 | 跌破趋势线代表趋势结构破坏 |
| 技术支撑位止损 | `价格跌破 ¥24.00` | 双底/前低支撑位 | 基于技术形态的支撑位 |

**系统默认值：**

- **固定止盈**: 成本价 × 1.20（浮盈+20%）
- **固定止损**: 成本价 × 0.92（浮亏-8%）
- **趋势止损**: MA20 × 0.98（跌破MA20留2%缓冲）
- **单票最大仓位**: 20%
- **单日最大亏损**: 不超过总资金2%

**注意：**
- 止盈止损条件必须合理，不能出现风控熔断了但止损还没触发的情况
- ATR 可以从 position-info 的 `atr_14` 字段获取，用于动态止盈止损计算
- 触发价必须有明确的数学计算依据，标注在括号内
- 每条条件必须有完整的 `**触发条件**`/`**操作**`/`**触发价**`/`**说明**` 字段
- **百分比写法**：买入（入场）时写 `100%` 表示"买入目标仓位的全部"，`50%` 表示"买入目标仓位的一半"，分阶段买入写 `30%`+`30%`+`40%` 合计 100% 正好买满目标仓位；卖出（止盈/止损）同理，`100%` 表示"卖出目标仓位的全部"，分阶段减仓写 `30%`+`30%`+`40%` 合计 100% 正好卖完目标仓位（实际持仓不足时按实际持仓卖出）。百分比都是目标仓位的固定基准，与当前持仓/缺口无关

### 阶段D：保存交易计划（用户确认后执行）

**等待用户确认后再执行此阶段。** 在阶段C中已将交易计划展示给用户，用户确认同意后，才将 Markdown 内容通过以下脚本保存到文件系统并解析入库：

**方式一（推荐）：通过 `--file` 参数传入草稿文件**

```bash
python agent_config/skills/trade-plan/scripts/save_plan.py --file data/trading_plans/draft_{stock_code}_{trade_date}.md
```

草稿文件内容格式为 JSON：
```json
{
  "stock_code": "600519.SH",
  "plan_type": "sim",
  "trade_date": "2026-08-01",
  "markdown": "---\n..."
}
```

**方式二：通过 stdin 传入 JSON**

```bash
python agent_config/skills/trade-plan/scripts/save_plan.py
```

通过 stdin 传入 JSON：

```json
{
  "stock_code": "600519.SH",
  "plan_type": "sim",
  "trade_date": "2026-08-01",
  "markdown": "---\n..."
}
```

脚本会自动写入 `data/trading_plans/{plan_type}/{stock_code}_{trade_date}.md` 并解析到数据库。

## Error Handling

- **保存失败**：检查 JSON 格式是否正确，stock_code 是否带后缀
- **解析失败**：检查 Markdown 结构是否严格遵循模板，尤其是 YAML frontmatter 和章节标题
- **用户不同意**：如果用户对生成的交易计划不满意，要求修改，则根据用户反馈调整后重新展示，直到用户确认再执行阶段D
- **保存后需手动「生效」**：交易计划保存后默认未生效，用户需在交易计划页面点击「生效」按钮才会被执行引擎读取
